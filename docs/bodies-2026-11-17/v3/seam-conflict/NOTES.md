# seam-conflict arm (exploratory, 3 seeds, no gates, no stats)
Scripts: run_pair.sh, run1.sh (one run), sum1.py/sumc.py/sumt.py (summaries). Job lists: r1cmds.txt, r2all.txt, r3all.txt, r4all.txt, r5all.txt, r6all.txt, r7all.txt (each line = rung name seed scenario flags; every number below is from the readout.json files in r1..r7).
Dirs: r1 pair 12000 steps; r2 crowd mutation off; r3 crowd mutation ON (A step8 marks, B bud-marks step40 no grow gate, C = B + all three gates; _blind = --tag-blind, _same = --tags same); r4 seam cost / raid sweep (B settings); r5 seam cost alone, r5w wound-in-crowd; r6 grow-gate confound; r7 matched control for C (--tol 128).

## Findings
- Rung 1 (pair, 7 settings x 3 seeds, 12000 steps): two bodies stay two in all 21 runs, 2 big patches throughout, 0 patch deaths, seam 1-26 permille (0 with GATE_GROW). Bodies keep growing (320-1527 cells).
- GATE_GROW zeroes the seam, so SEAM_COST/RAID never fire with all three gates (burn 0, raided 0 in r2/allgates, r3/C). Seam knobs only act with GATE_GROW off.
- Rung 2 (crowd, no mutation, 3 founders): without GATE_GROW (sc1raid2, ssg_sc1raid2, sc3raid4) one founder clade holds 92-96% of cells (sweep-to-mat); the other two stay ~120-280 cell patches (lone-body size) and live. Burn 2.3e5-3.8e5, seam 4-8 permille vs 17-25 plain. 5 founders (3 seeds): largest clade 44-82%, 5 distinct marks, seam 14-29 permille, basins 72-116 median vs 160-185 plain (ssg_sc1raid2: more, smaller basins). With all three gates: 3 components (3 clades), largest 79-96%.
- Seam cost alone with GATE_SHARE+SIGNAL (r5 sc8raid0, sc20raid0, B-style bud-mutated marks): replaced tiles ~600-1050 per 20000 steps vs 23-56 for --tag-blind and 29-92 without the share/signal gates; ~40-210 replaced at t>=10000. Raid cancels it (sc2raid0 ~640-1490, sc2raid2 ~30-150). Real but slow border creep, patch births/deaths ~5-27/0-10 per run; dominant clade still 66-97% at end.
- Rung 3 (mutation on, tag mutation, 3 seeds): A (step 8 <= tol, drift chains): one clade 71-97%, same gene means as A_blind within seed (grow 698/608/611 vs 684/609/611). B (foreign buds, step 40): 5-16 big patches, largest 63-93% (blind 57-90%). C (all gates + bud marks step 40): 7.5/12.4/8.0 components (blind 1.0), seam 0, patches frozen from t=6000 (e.g. s2 top 2932/1181/1003/592/415 at every 2000-step sample to 20000; patch births/deaths 0/0; replaced tiles 0-4), distinct marks 5/7/6 constant after t=2000. Failure mode: jammed-mosaic (territories separated by dead lines, frames r3/C/s2/frame-t20000.png). Territories are clade-sized (400-3000+ cells), not 170-cell bodies; basins 114/64/76 per run.
- Matched control for C: --tol 128 (gate and permuted scan on, everything matches) gives 1.0-1.1 components and one patch holding 100% (r7). So C's mosaic is due to the marks, not to the gate code.
- Wound (r5w, 3 seeds each, root spared in all): C refills the disk (26-30 of 32-40 killed cells live at +1500) mostly with the pre-wound mark (foreign 0/0/7 of 26); sc20 gated: 20-31 live, foreign 0/0/13 (seed 3 basin was foreign to its own refKin).
- Gene means: no consistent difference from the tag-blind control in A/B; C differs in direction in rim (58/3/53 vs 39/76/49) but not consistently. Not claimed.

## Confound / model observation (not fixed)
GATE_GROW also switches growth to a per-step random permutation scan. With tags all the same (nothing foreign), --gates grow gives a different trajectory from gates off: crowd boom delayed to t=7600/1400/800 (seeds 1/2/3) instead of 1000/1000/1000 (r6 grow_same, grow_tol128, allgates_same identical). Seed 1 keeps three ~170-cell bodies (494 cells total) for 7600 steps with NO recognition involved. --tag-blind (raster scan, boom at ~1000) is therefore not a matched control for GATE_GROW arms; the matched control is --tol 128 (r7) or --tags same without mutation.
Other: pair 12000 steps shows bodies growing, not holding at ~170.
