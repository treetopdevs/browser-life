Decisions

D1 — Complete the next operational gap

Expose supported coordinator settings in Compose and provide an opt-in client-address path through Caddy. This makes documented configuration usable without inventing a new scientific feature.

D2 — Trust no upstream by default

Use an empty static proxy allowlist by default, strict right-to-left parsing of X-Forwarded-For, and replace the upstream header with the single resolved client address. Document explicit Traefik CIDRs, isolated coordinator networking, and separate live verification before enabling per-address join limits. Do not default to all private networks.

D3 — Preserve release defaults

Pass through only existing runtime settings: BL_TRUST_FORWARDED_FOR, BL_ISLAND_JOINS_PER_ADDRESS, BL_MAX_ISLANDS, BL_CORS_ORIGINS and BL_LEASE_MS. Blank values retain coordinator defaults. Garden scheduling stays off, garden routes stay private, coordinator has no published port.

D14 — Cleanup failures must remain failures

Both Sol source reviews and Sonnet found that Docker failures could be treated as empty/absent resources. The helper now requires successful invocation-labelled enumeration; the workflow preserves all query/removal/postcheck statuses. Fault probes confirm failed queries or survivors exit nonzero and retain scratch evidence. Only confirmed empty state permits deletion. Diagnostics are logged before resource removal; forced local termination and platform cancellation limits are explicit.

D15 — Prove both packaging and HTTP sensitivity

Require two disposable canaries: missing packaged lab page and missing served assets. Each must fail its named assertion with the expected content failure; a generic Docker/startup error is not accepted. Tighten the forwarded-address test's final forged IP, compare complete error bodies, and preserve failure reports. No canary image is published.

D16 — Reject ambiguous canary and teardown outcomes

The final Sol CLI review found that an expected content failure could hide a cleanup/runtime error, and native teardown could silently accept a live process. Require canary exit1 plus a named JSON assertion and JUnit showing exactly one failure with zero errors. Fault probes accept only the assertion-only case and reject extra hook/runtime errors. Native Caddy escalates TERM to KILL and confirms exit; a TERM-ignoring probe is stopped. No timeout or signal alone qualifies as a passing canary.
