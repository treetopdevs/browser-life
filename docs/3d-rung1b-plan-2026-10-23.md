# Rung 1b plan: the slab (2026-10-23)

Rung 1a closed with a re-rule to **go at R = 3** using a workgroup of 8 × 8 × 4 cells, block 1 (see
`docs/3d-rung1a-bench-2026-10-22.md`, amendment of 2026-10-23). On the idle M3 Pro that shape runs one
slab affinity pass (256 × 256 × 8, R = 3) in 217 µs, 2.21 times today's 2D affinity pass. This note fixes
the design of the slab and the order of the work before any code is written. The check that ends the rung
is the one already written in `docs/3d-brainstorm-2026-10-22.md` §5; this note only pins the parameters
that the check left open, and it does so before any run.

Code references are to the tree at `ef903a29`.

## 1. What the slab is

- **Grid.** 256 × 256 × D with D = 8: one tile (`tilesX = tilesY = 1`). x and y wrap, as today. **z is
  closed**: layer 0 is the surface and layer D − 1 is the floor, and nothing wraps between them. With 8
  layers and R = 3 a wrapped z axis would make the floor a kernel neighbour of the surface and defeat the
  hypothesis the rung tests.
- **Light** falls on layer 0 and is shaded layer by layer by the biomass above (§3.6).
- **Matter and energy** are closed and open exactly as today: the conservation residual stays exactly 0.
- **Out of scope for v1** (rejected by `validateConfig` when the slab is on): islands and archipelago
  (`tilesX`/`tilesY` > 1), migration, ponds, declared cells, heritable kernel shapes (`shapeReach`), genes,
  lossy takeover, injury, adhesion, the patches and sweep light modes, wander, and lesions. Each is a later
  addition with its own golden cases. **Sinking is deferred** too, so v1 tests one hypothesis: shade alone.

## 2. Where the code goes

Every rule variant so far is an optional `WorldConfig` key, absent from `defaultConfig()`, branched inline
in `step.ts` and compiled into constants in `shaders.ts` (`config.ts:140-388`, `step.ts:117-118, 236-253`,
`shaders.ts:143-175`). The slab cannot follow that pattern: it changes indexing, `nb()`, dispatch shape, the
kernel table, every neighbourhood (4 → 6, 8 → 26, 9 → 27 sources) and the genome length, so inline
branches would touch nearly every line of the RULE_VERSION 1 code path. The precedent for a variant in its
own module is `packages/sim-ref/src/cells.ts`.

So the slab lives in **new files** and shares only primitives that are layout-free: `growth()`, `w1d`,
`mulShareD`, `cat` and the integer helpers in `int.ts`. `diffOut`, `controllerForward` and `mutateInPlace`
are hard-coded to quarter portions, the 10 → 8 → 8 offsets and 160 weight bytes (`step.ts:805-808,
816-825, 839-860`), so the slab gets its own `diffOut6`, `controllerForward3` and `mutateInPlace3` in
`step3d.ts` and leaves the 2D ones untouched:

| package | new file | contents |
|---|---|---|
| schema | `layout3d.ts` | channels, controller sizes, genome layout, RND slots, MOT packing for the slab |
| schema | `kernel3d.ts` | `buildKernel3(R)`, lifted from `experiments/3d-bench/kernel3d.ts` with its asserts |
| schema | `genome3.ts` | encode/decode, hex, `generalistGenome3`, `liftGenome` (2D → slab) |
| schema | `world3.ts` | slab founding (ball founders), `validateState` for the slab layout |
| sim-ref | `step3d.ts` | `RefSim3`: the executable specification of the slab |
| sim-gpu | `shaders3d.ts`, `gpu-sim3.ts` | the WGSL twin and its pipelines |
| metrics | `census3.ts` | 6-connected components in the slab, per-layer role sums |
| tools | `slab-screen.ts`, `slab-readout.ts` | the rung 1b runs and the readout of the fixed check |

Shared code is edited only where it must be:

- `config.ts`: one optional key `tileD` (the slab is on exactly when it is present) and one optional key
  `lightK` (§3.6). Both stay absent from `defaultConfig()`, so every existing config hashes as before.
  `cellCount` multiplies by `tileD` only when present. `validateConfig` checks the slab keys and the
  exclusions in a new `validateSlab`.
- `world.ts` `validateState` and `checkpoint.ts` decoding: pick the slab layout's genome length when
  `tileD` is present, and for a slab require E ≤ 2^27 and S ≤ 2^27 (not today's 2^28, `world.ts:167-170`).
  This applies at every way a state enters: founding, `GpuSim3` upload, checkpoint decode. Without it a
  state admitted at 2^28 could overflow transport before react ever applies the lower cap (27 sources
  can all send their whole E to one cell when `spread = 0`).
- `accounting.ts` `canonicalGenome` (`accounting.ts:69-78`) takes the genome channel count as a
  parameter, default 44, and `stateHashWords` and checkpoint encoding pass 49 for a slab. Today it derives
  the cell count from `GENOME_CHANNELS = 44`, which on a 49-word genome would zero live words. With the
  default unchanged, every 2D hash and checkpoint stays byte-identical.
- A small factory (`createSim(cfg)` in sim-ref and sim-gpu) that returns `RefSim`/`GpuSim` or
  `RefSim3`/`GpuSim3`. The golden runner and the experiment runner call the factory.
- `golden.ts`: new `slab-*` cases. `golden-hashes.test.ts`: their pins added under `PINNED[1]`, with the
  usual comment that every pin above is untouched.
- `runner.ts` and `observe.ts`: `runner.ts:1341` delegates to `observeCensus`, which always calls the 2D
  `census()` (`observe.ts:93`); that census wraps y within each tile and has no z edges
  (`census.ts:123-128`). For a slab, `observeCensus` calls `census3` instead, and every downstream metric
  that assumes 2D geometry is written as absent rather than computed on the flattened grid (M5 lists them).
  The runner writes `layers.tsv` (§5.2).
- `docs/rules.md`: a new section "The slab" with the bounds in §4.

Apart from the `canonicalGenome` parameter above, `stateHash` needs no change: it digests the canonical
config and the whole `cells` and `genome` arrays (`accounting.ts:90-99`), and the slab adds no other state.

## 3. The slab's rules

Indexing is `i = z·W·H + y·W + x`. `nb3(x, y, z, dx, dy, dz)` wraps x and y within the tile and returns
"outside" when `z + dz` leaves `[0, D)`. Every pass below says what "outside" means for it.

### 3.1 Layout (`layout3d.ts`)

- Cell channels: unchanged (A, B, C, P, E, S, MOT; 7 channels, channel-major). MOT packs three signed
  bytes: `(mx + 128) | (my + 128) << 8 | (mz + 128) << 16`.
- Controller 11 → 8 → 9. Inputs: today's ten (`layout.ts:27`) plus `SGZ` at index 10. Outputs: today's
  eight plus `MZ` at index 8. Weights: W1 88 bytes, B1 8, W2 72, B2 9: `NN_BYTES3 = 177`.
- Genome: LIN_HI, LIN_LO, PARAM0, PARAM1, then 45 weight words (177 bytes plus 3 padding bytes that are
  always 0): `GENOME_CHANNELS3 = 49`. Mutation picks among `NN_BYTES3 + 3` slots, never the padding.
- RND slots: `DIFF3` takes 1..18 (6 directions × 3 species) plus `DIFF_ROT` at 19; slots 20..39 keep their
  meanings.
- `ROLE_WORDS = 2` with today's packing (`photo | grow << 16`, `decomp | resp << 16`, each saturated at
  65,535; `step.ts:690-692`).

### 3.2 Affinity

The kernel is `buildKernel3(3)`: 92 taps, weight sum 9,624 (the bench's asserts carry over, including
"dz = 0 reproduces `buildKernel`"). A tap whose `z` is outside contributes mass 0, and the sum is still
divided by the full weight sum, so a cell at a wall sees what it would see next to empty water.
`conv ≤ 255 · 16,383 · 92 < 2^29`. Growth and `U` as today (`step.ts:245-252`, `growth()` at 754-763).

**Calibration.** Today's `mu = 60, sigma = 20` were tuned for a 2D disc at R = 9; a 3D ball at R = 3 has a
different neighbourhood mass, so they will not carry over. Milestone M4 sets them (§6).

### 3.3 Flow

- Sobel 3 × 3 × 3, separable: smoothing `[1, 2, 1]` on the two other axes, difference `[−1, 0, 1]` on the
  axis itself. Per-axis absolute weight sum is 16 (against 4 in 2D), so each gradient is divided by 4
  (truncation towards zero, the same in WGSL) to keep today's scale: `|g| ≤ 4 · 16,383` again, and every
  downstream bound in `step.ts:279-281` holds unchanged.
- A neighbour outside in z reads the cell's own value (zero gradient at the walls).
- `disp[i]` packs three bytes `(dx + 64) | (dy + 64) << 8 | (dz + 64) << 16`. `dmax = 64 − spread` per
  axis, as today. The motility term adds `MZ` scaled by the same gain.

### 3.4 Transport

- 27 sources, box half-width `hw = 32 + spread`, `D1 = 2·hw ≤ 128`.
- Per-axis weights `wx = w1d(dx, −ox, hw)` and the same for y and z (`step.ts:780-784`).
- The share sent to a neighbour is computed one axis at a time:
  `share = mulShareD(mulShareD(mulShareD(q, wx, D1), wy, D1), wz, D1)`. Each call is exact because
  `w ≤ D1 ≤ 2^14` (the precondition at `step.ts:786`). The nested floors are not the floor of the product,
  but they are deterministic and the source keeps everything not sent, so conservation stays exact.
- A target outside in z receives nothing; that share stays with the source.
- The genome lottery draws over the 27 lots; the winner copies all 49 words and MOT.

### 3.5 Diffusion of A, C and S

- Six directions `+x, −x, +y, −y, +z, −z` numbered 0..5, so `d ^ 1` is still the opposite direction.
- Portion: `portion_d = floor(q / 6) + [((d + rot) mod 6) < (q mod 6)]` with
  `rot = draw(base, DIFF_ROT) mod 6`, then `mulFrac(portion_d, De · 4, 10, draw(base, DIFF3 + d·3 + sp))`
  exactly as today (`step.ts:805-809`). The total fraction that leaves a cell is still `De / 256`, as in 2D,
  spread over six directions; `De ≤ 256` keeps it at most 1.
- A portion aimed outside in z is never sent and stays with the source.
- Gating (`De = D · gateK / (gateK + P_t + P_n)`) and waste routing unchanged.

### 3.6 Light

Light is computed once per step, before react, from the cells as they stand after transport:

- `L(x, y, 0) = light2d(x, y, step)`: today's function (`step.ts:150-181`) restricted to the `uniform` and
  `gradient` modes, with seasons allowed.
- `L(x, y, z) = (L(x, y, z − 1) · T(m)) >> 8` for z ≥ 1, where `m = min(B + P, 16,383)` of the cell
  directly above, `(x, y, z − 1)`, and `T(m) = floor(256 · lightK / (lightK + m))`.
- `lightK` is a new optional config key (1 ≤ lightK ≤ 2^16). Products stay below `255 · 256 < 2^16`,
  `256 · lightK < 2^25`, and `L ≤ 255`, so `mulShr(·, L, 8)` keeps its bound.
- A cell does not shade itself. Light is derived each step and is not state.

On the GPU this is one pass with one thread per column walking z = 0..D − 1.

### 3.7 React

As today (`step.ts:473-703`) with L from §3.6, and:

- `SGZ = clamp(divi(muli(cap24(S_below) − cap24(S_above), sg), 4), −127, 127)`: the same cap at 2^24 − 1,
  truncating division and clamp as SGX and SGY (`step.ts:538-552`, `shaders.ts:771-784`). Without the cap,
  `signalGain = 127` times a signal difference near 2^27 wraps and reverses the sensor. An outside
  neighbour reads the cell's own S (after the same cap), so SGZ at a wall sees only the one real
  neighbour.
- `MOT` from MX, MY, MZ.
- Energy pools capped at `POOL_MAX3 = 2^27` wherever today caps at `POOL_MAX` (§4).
- The abiotic recycling `C · L` uses the shaded L, so recycling also slows with depth.

## 4. Bounds for `docs/rules.md`

| bound | 2D | slab |

| signal sensors | `cap24` then `· sg` (≤ 127), `< 2^31` | SGZ the same |

| Sobel gradient | `≤ 4 · 16,383` | `≤ 16 · 16,383` before ÷ 4, `≤ 4 · 16,383` after |

| diffusion | quarter portions, `De ≤ 256` | sixth portions, `De ≤ 256` |
| cell count, LIN_LO | `≤ 2^24`, 22 bits | 2^19 cells; fits |

The `validateConfig` checks follow the table.

## 5. Founders, control and readout

### 5.1 Founders and the control

- Founding preset `slab-spots`: 8 founders, each a ball of radius 3 at a seeded random `(x, y, z)`,
  nutrient 32 in every cell, biomass 64 in the balls (the 2D `spots` values, `presets.ts:74-86`).
- Founder genome: `liftGenome(generalistGenome(mu, sigma))`. The lift remaps W1 by `(i, j)` and W2 by
  `(j, k)` into the 11 → 8 → 9 layout, sets every SGZ and MZ weight to 0, and copies the header words. A
  byte copy would be wrong because the strides change.
- The `neutral` control (`conditions.ts:25`) expresses `generalistGenome3`, the same lifted generalist, so
  the two arms start from the same phenotype.
- Light for the check: `uniform`, `lightBase 40`, `lightAmp 200` (240 at the surface), seasons off.
  `lightK` is set by M4.

### 5.2 Readout

- Census every 1,000 steps with roles read on every census (`deepEvery = 1`). The ten censuses ending at
  step 300,000 are steps 291,000 … 300,000.
- For each census, `census3` writes one row per layer to `layers.tsv`: step, z, photo, grow, decomp, resp
  (sums over the layer), and the number of saturated role words in that layer.
- `tools/slab-readout.ts` applies the check from `docs/3d-brainstorm-2026-10-22.md` §5 verbatim: layer
  groups top = z ∈ {0, 1}, bottom = z ∈ {6, 7}; photo share and D as defined there; bar `m + r` from the
  neutral seeds; 3/3 go, 0/3 pause, 1-2/3 extend to 6 + 6 and need 5 of 6.
- **An undefined neutral D** (a neutral seed whose top or bottom group has no activity) is not dropped,
  replaced or rerun. The bar cannot be formed, and the outcome is **pause: control undefined**, both in the
  first 3 + 3 and in the extension. An undefined evolving D fails that seed, as the brainstorm says.
- Seeds: 1, 2, 3 for both arms; 4, 5, 6 for an extension. Calibration (M4) uses seeds 101, 102, 103 so it
  never sees the check's seeds.

## 7. Risks

- **The step may be slower than the affinity numbers suggest.** Only affinity and a transport stub were
  timed; react and transport scale with 8 times the cells. M3 measures this before anything depends on it.
- **R = 3 makes organisms small.** A 2D organism today spans a kernel of radius 9; a slab organism spans
  radius 3 in three dimensions. Calibration may find no regime that both persists and stays below a carpet.
- **Light depth may be too steep or too flat.** M4's qualifying window (5 % to 80 % at the floor) keeps the
  check from running in a world where depth is trivial or where nothing lives below the surface.
- **Neutral uses the generalist, not the founders.** That is today's definition (`step.ts:124`) and both
  arms here start from the same lifted generalist, so the comparison stays fair.
- **8 layers is shallow.** Top 2 and bottom 2 groups leave 4 middle layers; a stronger version of the
  question is rung 2's jar.

either stayed sparse (or died) or covered most of the slab, and shade was only strong where biomass covered
most of each column. The qualifying window asked for a sparse world that also shades its floor, and these rules did
not produce one anywhere on the grid. This is a statement about the grid and the founding, not about every
possible slab: nutrient per cell, founding and the window itself were held fixed.

**Not decided here.** Whether to stop the 3D line, or to re-rule (as rung 1a was re-ruled) with a new,
dated, pre-stated calibration — for example a different control knob such as nutrient per cell, or a
different qualifying window — is the user's call. Any re-rule goes in its own dated amendment before any new
run. It would be informed by these results, so it is a new calibration on fresh runs, and the check keeps
seeds 1-6, which no calibration has seen.

## Amendment 2026-10-24: re-rule M4 with nutrient per cell as the knob

**Status: approved by the user on 2026-10-24, before any M4b run.** It was drafted and reviewed (Codex Sol,
two passes) before approval; the code of "Before any run" is committed with this section, and the grid runs
after that commit.

This is a re-rule in the sense of the rung 1a amendment: M4 found no qualifying setting, and this section
fixes a new calibration before any new run. It is informed by the M4 results, so it says which observation
informed which choice (Provenance, below). Everything in §1-§5 not named here is unchanged, and the check
itself (§5.2 and the brainstorm's rule: D, the bar `m + r`, 3/3 go, 0/3 pause, 1-2/3 extend) is unchanged.

### Why nutrient

- **What "living" counts.** A cell is living when its genome slot holds a lineage id. The slot is cleared
  only when B = 0 and P = 0 (`shaders3d.ts`, end of react), so a cell with any biomass or polymer counts,
  however little. Living is coverage, not mass.
- **What the carpets were.** In M4 the carpets were 99.5-100 % living with floor light 0.79-0.83 at
  `lightK 1024`, and 88-100 % living with floor light 0.44-0.61 at `lightK 256`. Inverting the integer light rule with the same `B + P` in
  every layer, those ratios correspond to about 21-33 per cell at `lightK 1024` (the integer rule has
  plateaus: 21-24 gives 0.833, 25-28 gives 0.8125, 29-33 gives 0.7875) and 18-30 at 256: the same order as
  the 32 units of nutrient every cell started with. This is inferred from the light, not measured
  (M4 did not record mass per cell, and real columns are not uniform). The reading is that life spread most
  of the matter as a thin film everywhere.
- **The hypothesis (a reason to try the knob, not a prediction).** The affinity pass computes
  `u = 4 · (kernel-weighted mean of B + P)` (`massUnit 256`) and `U = growth(u; mu, sigma)`. U steers flow
  (matter moves up its gradient) and is a controller input; it does not itself make biomass. U is flat at
  −256 outside `mu ± 3 sigma` and positive only within about `± 1.2 sigma`. A film of 18-33 per cell has
  `u ≈ 70-130`, at or above the top of the non-flat range for most of the grid (for example 50 at mu 30,
  sigma 8; 101 at mu 60, sigma 16), so the interior of a carpet sees no gradient to gather matter into
  bodies. With N between 8 and 24, a film holding all the matter would sit at `u ≈ 32-96`: inside the live
  range for the lower N, and near its top for the higher mu and sigma at the higher N. Whether that gives sparse, dense bodies or a thinner carpet is what the calibration
  measures: N sets the closed matter budget (with the founder balls' biomass on top), not occupancy or local
  density, and evolving lineages carry their own mu and sigma, which can drift.
- **Precedent.** In the 2D big storm (shared-garden test 6.1), nutrient 32 starved, 64 carpeted and 48 was
  populated on 2 of 3 seeds: nutrient moved a 2D world between starving and carpeting, and the populated
  band was narrow.

### The new grid (fixed now)

- **Nutrient per cell** `N ∈ {8, 12, 16, 20, 24}` (the `slab-spots` founding's `nutrient`; founder balls
  keep biomass 64 and energy 128).
- `mu ∈ {30, 40, 50, 60}`. mu 20 is dropped to keep the grid at 80 settings: at N = 32 every mu 20 world
  died or held at most 2.8 % of cells with floor light 0.999. This is a judgement, not a result: mu 20 at
  lower N is untested.
- `sigma ∈ {8, 16}` (at N = 32, sigma mattered most at mu 30, lightK 256: 44-51 % living at 8, 0.6-24 % at
  16; at `lightK` 1024 and 4096 both carpeted).
- `lightK ∈ {64, 256}`. Sparse worlds shade only in occupied columns, so per-column shade has to be strong:
  with `B + P = 64` in a body, `T` is 128 at `lightK 64` (half the light kept per layer) and 204 at 256
  (0.80 per layer).
- 5 × 4 × 2 × 2 = 80 settings, seeds 101-103, evolving arm, 50,000 steps: **240 runs**. At M4's speeds
  (about 4 min per run on the M3 Pro, about 5.5 on the M1 Max) this is about 8 hours on the two Macs with
  M4's share of early extinctions, about 9 hours with none, plus at most 9 neutral runs. No paid compute.
- Seeds 101-103 again, so M4's N = 32 rows at the same mu, sigma and `lightK 256` are the direct comparison.
  The check's seeds 1-6 stay unseen by any calibration.

### What each run records (fixed now)

Each result records: condition (`treatment` or `neutral`) and `cfg.neutral`; preset id and the init it
used (kind, founders, nutrient, biomass); the full config; `RULE_VERSION`; requested and actual steps,
and the extinction step if any; matter conservation and the energy residual. Measurements: the living
fraction every 5,000 steps (as before); `dense` (cells with `B + P ≥ 64`, already counted by the stats pass)
every 5,000 steps; mean light per layer at the end (as before); and from the final state (already read
for the conservation check) and a final `readRoles()` (new, before the simulator is destroyed) living cells
per layer, mean `B + P` per layer, and the sum of the
last step's photo, grow, decomp and resp counts per layer. Only the conditions below decide anything.

### Qualifies (fixed now)

A setting qualifies when all three seeds meet all of:

1. **Window, unchanged:** living cells between 1 % and 50 % of all cells at step 50,000, and mean light at
   layer 7 between 5 % and 80 % of mean light at layer 0.
2. **Settled (new):** the living fraction is also between 1 % and 50 % at steps 40,000 and 45,000, and
   between step 40,000 and step 50,000 it changes by at most 5 percentage points and by a ratio between 0.8
   and 1.25 (both must hold). M4's two rising nearest misses (33.4 → 44.0 % and 37.3 → 44.9 %) fail this; it
   is a pre-stated drift bound, not a proof that a world has stopped changing.
3. **Both ends alive and active (new):** at step 50,000, in the top group (z ∈ {0, 1}) and in the bottom
   group (z ∈ {6, 7}) each, at least 1 % of the cells are living (1,311 of 131,072) and the summed role
   counts of the last step are above 0. The check's D is undefined when a group has no activity, which fails
   an evolving seed and pauses the whole check for a neutral one (§5.2). This guard makes that less likely;
   it cannot guarantee activity over the check's window at step 300,000.

### Pick (fixed now)

Among qualifying settings, the highest **median over the three seeds of living cells at step 50,000**, as
before (the smallest change; the settled condition now guards the carpet edge). Ties go to the larger
`lightK`, then the larger `sigma`, then the smaller `mu`, then the larger `N`. That order is complete.

### Neutral stage (new, fixed now)

The check also needs the `neutral` arm alive at depth. Take the qualifying settings in pick order, at most
the first three. For each, run `neutral` seeds 101-103 at 50,000 steps. The pick is the first setting whose
three neutral runs each end with at least 1 % living and meet condition 3. At most 9 extra runs. The picker
reads the neutral results and prints the final PICK itself; nothing in this stage is chosen by hand.

**Failures.** A run that goes extinct is a result (living 0; it fails the window). A run that fails matter
conservation, has a non-zero energy residual, crashes, or records a config, init, condition, seed or rule
version other than its job's is not a result: the picker refuses to select anything while one exists, the
cause is found and fixed, and that job is rerun. Seeds are exactly {101, 102, 103} per setting, every grid
tuple appears exactly once per seed, and a result with a missing or malformed measurement is refused. If no qualifying setting passes, or none qualifies, stop and write it up; this is the last
calibration of rung 1b under this note.

### Provenance: which M4 observation informed which choice

- Carpets at 88-100 % living with floor light implying roughly 18-33 per cell, which puts a carpet's u
  above most of the grid's live affinity range → nutrient as the knob, and N below 32.
- mu 20 sparse and unshaded at N = 32 → mu 20 dropped.
- The nearest miss rising at 50,000 → the settled condition and its drift bound.
- No run with shade at low coverage, and sparse worlds shading only where they live → `lightK` 64 and 256
  rather than 1024 and 4096.
- The check pausing on an empty bottom group (a risk M4 did not test) → the both-ends and neutral stages.
