All 18 food tool directories map to these 11 screens. Model, horizon and seeds are from a scan of each tools/<screen>/explore.ts; step 1 re-reads them, and reads the compared arms, from the same files.

Design

  • Which model runs. The eight models are a copy chain, and the newest claims the older modes are preserved. A parity test checks that claim per screen, mode and seed (state equal at ticks 0, 500 and the screen's own final tick). Pass: the page uses only the newest model. Any failure: that screen loads its own model. Uniform food always runs on the hungry-shapes model. No model file is edited either way.
  • Known wrinkle. Uniform endurance changed food allocation under the same mode name hungry-shapes uses. The page shows them as different arms.
  • Drawing. New render.ts written from the hungry-shapes drawing code; band overlay from each model's own geometry helpers.
  • Built-in replay check. With food-replays done, "compare with the recorded run" shows whether the live census matches the recording tick for tick.

Parity passes or the fallback is in place; live census equals a recorded one for at least one replay per screen; gates green.

slab-viewer

See the 3D world

A private page /slab/. The slab is only four cells deep, so it is drawn as it is: four layer tiles and one larger top-down view that combines them, with a slider to isolate a layer. Two worlds: the slab ecology from rung 1b, and cyclic competition (three types that beat each other in a ring).

Set expectations. Neither world passed its gate. Calibration found no ecology setting that qualifies (living fraction around 0.001 in the sampled row), so that view may be nearly empty; cyclic competition stopped at Gate 0. The viewer shows what these worlds do, which may be little.

Design

  • No volume renderer. Depth is 4; tiles plus a projection show everything.
  • Read back first, draw on GPU only if needed. 128 × 128 × 4 is 65,536 cells. The first version uses the existing cell readback and a 2D canvas: no new shader, and the picture is provably the simulated state. A direct GPU render pass comes only if that is too slow at 256 × 256 × 4.
  • Simulators are imported, never edited: gpu-sim3.ts for the ecology, the hash-pinned gpu-sim3-rps.ts and world.ts for cyclic competition.
  • Picture check. A CPU test runs a tiny 8 × 8 × 4 state through the colour mapping and pins the output, so layer order and wrap direction cannot silently flip.

Steps

  1. Spike, half a day at most: create the real 3D kernel in Chrome from a lab page, step it, read cells back. If it fails, stop and report.
  2. Colour mapping and layer layout as pure functions, with the pinned test.
  3. Page with the ecology world and a census strip.
  4. Add cyclic competition. No registered operating point exists (Gate 0 ended in GATE-0-STOP), so the default is a recorded exploration setting from GATE0-EXPLORATION-2.md, labelled as exploration.
  5. Private-page checklist, e2e with WebGPU flags, gates, Codex review.
  6. Optional: GPU render pass; a "twin difference" view showing where a perturbed twin diverges (the regime meter, live).

Gate

Spike passes; pinned picture test; e2e shows non-blank canvases and a moving step counter; frame pacing recorded at 128 and 256.

Decisions

  • Base and landing. Both 3D branches are local, unpushed and forked from main at 3f44c319. Build on claude/3d-cyclic-rps (recommended: it has both simulators) and leave landing for later, or rebase the 3D line onto main first (much larger; not worth it for a viewer alone).
  • First world, if only one: cyclic competition is the more watchable; the ecology is what the 3D line was about.
  • The 3D line is closed at rung 1b. This is for looking, not for reopening it.
