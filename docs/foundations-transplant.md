# Foundation cell-packet primitives

`tools/lib/foundation-transplant.ts` is a pure preparation layer. It makes exact cell extraction, restoration and placement inspectable before any garden assay is run. It does not certify viability, reproduction, adaptation, competition, or resource-matched controls.

`extractCellPacket(source, indices)` copies the specified sorted cell indices into an `intact` packet. Each record carries all seven channel values (A, B, C, P, E, S, MOT) and all 44 packed genome words. The packet records the source physics hash, step, complete canonical configuration, geometry, exact per-species inventory, matter, energy, and its own SHA-256. Every indexed cell must be bound and carry the same lineage and genotype. Mixed, unlabelled, duplicate and malformed packets are rejected, rather than silently interpreted as a single inoculum. This restricted API cannot transplant an intact mixed collective; supporting that would require a separate, explicit multi-lineage protocol.

The source physics hash is the project's 64-bit `stateHash`, not a SHA-256 of an external checkpoint file. An assay runner must first authenticate the source checkpoint against its verified replay cache and record that file's SHA-256 separately. Packet validation detects accidental or local packet modification; it cannot independently establish original-bundle provenance.

`exciseCellPacket` clears exactly those seven channels and 44 genome words at the source indices. `restoreCellPacket` accepts the fully empty sites, writes all words back, and requires the original `stateHash`, which includes the physics configuration, time, MOT, light and heat ledgers, and reaction fluxes. This roundtrip checks that extraction itself is lossless. It does not show that an excised structure survives physical placement in a different world.

`toroidalMapping` uses an explicit source tile, destination tile, and integer `(shiftX, shiftY)`. It requires equal tile dimensions, keeps every selected cell in one source tile, and applies a tile-local toroidal translation. The full translation is bijective; the restricted destination indices are checked for collisions. `transplantCellPacket` requires a valid, mutation-disabled garden and an explicit injective lineage-ID map. Target IDs must be from the garden's past, unused anywhere in it, and representable under its lineage namespace. The tool rejects destination biomass, polymer, or lineage occupancy and any state bounds overflow. It replaces the full seven-channel destination records and all genome words, then returns those displaced records as an **export**. This is a replacement of local chemistry as well as structure, so the exported A/C/E/S and MOT values must be examined in an assay protocol. The operation never blends or silently normalizes the source and garden pools.

The transplant audit contains the exact mapping; destination records before replacement; per-species, matter, and energy inventories before, imported, exported, and after; and before/after physics hashes. For every conserved resource, it checks `after = before + imported − exported` exactly with integer arithmetic. It requires identical source and garden energy coefficients and rule version. The cumulative light, heat and flux ledgers remain unchanged by placement. A later simulation must define how exported material is held, discarded, or sham-transferred and account for that decision in the experiment; this primitive does not pretend the garden alone is a closed system after an intervention.

There are two deliberately separate inoculum arms:

- `intact` keeps the extracted morphology, chemistry, MOT, and genome. Different intact packets are different initial conditions even if they have the same total biomass or energy.
- `genomeOnlyArm(template, genotypeWords)` keeps one intact template's source indices and **every cell resource and MOT value** while replacing only genotype words 2–43. The lineage address is assigned through the same explicit transplant relabel map. `matchedGenomeOnlyInocula` accepts two genome-only arms only when they cite the same template and their complete non-genetic cell records and indices agree. It never labels intact packets as matched genome-only arms. A genome-only arm is derived and cannot be restored to the original source hash.

The controlled label-change test uses `RefSim` with mutation disabled and bijectively renames two adjacent lineages with different growth, motility and controller parameters. Thirty subsequent steps preserve all cell channels, non-address genome words, cumulative ledgers, and equality relationships among lineage labels. That is a local metamorphic check of the ID operation, not a general proof that every future code version or biological trajectory is label invariant. Physics and observer caches, garden pairing, conditioning, reciprocal placement, resident competitors, intervention shams, and assay stopping rules remain separate protocol decisions.
