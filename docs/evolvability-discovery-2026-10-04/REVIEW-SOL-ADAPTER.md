1. **P1 — Validation can use replacement code while claiming the original pin.** [tools/lib/discovery-pin.ts:34](/Users/nicholas/develop/browser-life/.claude/worktrees/codex-astra-critique-b22475/tools/lib/discovery-pin.ts:34). `verifyPin` checks files against `PIN.json`, then checks that record against itself. Change vendored code and consistently regenerate its hashes and `sourceDigest`: verification succeeds. Freeze subsequently checks the expected identity, but `pinnedValidator` does not, so an existing campaign can be validated under replacement code while its manifest still claims `24cef9e2…`. **Fix:** enforce the expected pin name, revision, digest and inventory inside `verifyPin`, for every caller.

2. **P1 — Initially seeded sites can be counted as new renewal.** [tools/discovery-pin-case.ts:74](/Users/nicholas/develop/browser-life/.claude/worktrees/codex-astra-critique-b22475/tools/discovery-pin-case.ts:74). Arbitrary observation sites become `sourceSites`, without checking the initial footprint. A `renewal-main` fixture containing two independently maintained, spread-zero founders can identify the first as its source; the unchanged reader counts the second seeded founder as an additional qualifying site. It can report RENEW without expansion, violating the renewal plan’s requirement for a site outside the initial one-site footprint. **Fix:** bind source identity to the initial artifact and refuse main fixtures with unsupported initial footprints.

3. **P2 — Empty control sites yield a vacuous positive.** [tools/discovery-pin-case.ts:74](/Users/nicholas/develop/browser-life/.claude/worktrees/codex-astra-critique-b22475/tools/discovery-pin-case.ts:74). `renewal-control` accepts `sites: []`. The pinned reader evaluates persistence with `sites.every(...)`, which returns true for an empty array. Even a founder-free world can therefore produce an accepted, supported control. **Fix:** require exactly the initialized control sites, with valid coordinates and no duplicates; reject empty or unrelated site lists.

4. **P2 — Partial census records pass validation.** [tools/discovery-pin-case.ts:251](/Users/nicholas/develop/browser-life/.claude/worktrees/codex-astra-critique-b22475/tools/discovery-pin-case.ts:251). Remove `kind`, `stateHash`, `lastStepRolesDigest` and `mutations` from an interior census, then update its canonical serialization, observation size and digests. The schedule, identities and readout still pass because those fields are checked neither structurally nor against artifacts at interior censuses. **Fix:** validate the complete census schema before accounting checks, including required fields, array lengths and numeric domains. Validate the observer snapshot’s completeness too, including `stepsObserved`.

5. **P2 — The pinned cost-retaining ablation cannot freeze.** [packages/schema/src/discovery.ts:507](/Users/nicholas/develop/browser-life/.claude/worktrees/codex-astra-critique-b22475/packages/schema/src/discovery.ts:507). Protocol validation always uses the workbench’s default-config key whitelist. It rejects `polymerTransport: false`, although the pin supports it and D5 explicitly assigns that ablation to pinned execution. **Fix:** make configuration validation backend-aware, allowing the reviewed pinned optional key and checking it under the pinned domain while retaining ordinary-backend validation.

6. **P2 — Freeze certifies unsupported assay schedules.** [tools/discovery.ts:147](/Users/nicholas/develop/browser-life/.claude/worktrees/codex-astra-critique-b22475/tools/discovery.ts:147). `freeze-check` receives only initial artifacts. A `renewal-main` case with 3,000 steps freezes successfully, but every execution immediately fails the 10,000-step requirement. Unknown assays and incorrect census cadence have the same gap; nonempty `segmentAt` is silently ignored. **Fix:** pass case specifications into freeze-check and reject unsupported assays, horizons, cadence and segmentation before creating the campaign root.

7. **P2 — Cell founders are omitted from manifest provenance.** [packages/runner/src/discovery.ts:168](/Users/nicholas/develop/browser-life/.claude/worktrees/codex-astra-critique-b22475/packages/runner/src/discovery.ts:168). Founder-panel construction handles only `"founders"`, excluding the new `"cells"` recipe. A pinned fixture executing an encoded builder genome therefore records `genomeHex: []` in `encodedFounderPanel`. **Fix:** collect genomes from both recipe kinds.
