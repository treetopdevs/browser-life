# Targeted vision screen: find worlds worth watching

26 October 2026. Base PR94, fb80e81a. The previous goal turn made concrete progress: the counted-matter aquarium is reviewed, committed and open. This slice completes a missing direction in the brainstorm rather than deepening that negative pilot. The proposed circulating current remains queued. No merge or deployment.

## Objective and limits

Build a working local screening app and a bounded targeted-selection loop over the existing particle recipes. Use actual local image/text embeddings, not a heuristic relabeled as vision. The prior wild breeder used novelty-oriented model selection and did not produce the desired behavior; here the target is explicit and performance is checked before search. Do not modify the particle model, old evidence, research kernel or integer physics. The particle toy is floating point and only promises replay in the same runtime.

The first target is visual: **many small separated clusters of colored dots on a dark background**. This is deliberately narrower than chasing or cell division. A mean of frame embeddings cannot establish temporal order, pursuit, heredity or evolution. Show actual animation and measured motion separately; label model scores as visual resemblance. This is an initial prototype of Candidate6, not completion of its speculative weekend CMA-ES/3D program.

## Local model and calibration first

Use openai/clip-vit-base-patch32 locally on CPU, inference/eval mode, no paid inference. Download public weights into an ignored local cache only if necessary; pin the resolved model revision and weight SHA256, package versions, CPU/device, preprocessing and prompt strings in output. Prefer safetensors when available, otherwise official weights loaded with weights_only. No remote code. Dependency installation stays in an ignored isolated Python environment.

Primary source: https://huggingface.co/openai/clip-vit-base-patch32 and https://github.com/openai/CLIP/blob/main/model-card.md. The encoder compares images and text and is not a motion classifier. Its fitness on our abstract images must be tested.

Render neutral 128x128 RGB frames, same palette and dot radii for calibration and simulations, no labels/overlays/food. Score cosine against exact target above minus maximum cosine to two fixed alternatives: **one large cluster of colored dots on a dark background** and **colored dots spread uniformly across a dark background**. Use normalized embeddings, no softmax confidence claim.

Calibration comprises nine deterministic fixtures: three layouts each of 12 compact separated clusters, one compact cluster, and uniformly spread dots; each has 120 dots and identical palette counts. Keep positions, renderer, prompts and seeds fixed before scoring. Require every clustered fixture's margin to exceed every single-cluster and uniform fixture's margin. Also score blank background, one dot and duplicated/frozen frames as diagnostic counterexamples, not training data. A failed calibration stops selection: retain scores and playable gallery, clearly say the judge cannot support this target. Do not prompt-tune until it passes or silently replace the judge with geometry. A future explicit revision is separate work.

## Plan-review resolutions (authoritative where earlier clauses differ)

Both reviews completed before implementation. This first screen measures **targeted visual resemblance with a separate activity floor**, not evidence that targeting improves search generally. Rankings and offspring changes remain descriptive. Keep raw cosine to all three prompts, margin, per-window frame standard deviation, and same-seed early/late comparisons. Human inspection can mark the judge **unsupported by inspection** even if numeric calibration passes; that stops further search expansion. Never call a high score life or adaptation.

Calibration expands to 54 fixtures: counts60/120/240 × layouts0/1/2 × groups1/3/6/12/uniform/seam6. Palette by global dot index modulo3. For each count/layout, require the margins of groups6,12,seam6 all to exceed both group1 and uniform, and to exceed blank and one-dot margins. Groups3 are diagnostic intermediate cases, no monotone counting claim. Every requirement must pass to select. Render freezes of representative target fixtures; repeated identical pixels must yield identical scores within1e-6. These are controls, not a temporal competence test. Fixed target/alternative strings remain unchanged. Failure is judge/target incompatibility; do not diagnose prompt wording as the cause without evidence.

Fixture positions are exact integer pixel coordinates. Centers: group1=(64,64); group3=(24,64),(64,24),(104,96); group6 Cartesian x20,64,108 and y32,96; group12 Cartesian x16,48,80,112 and y20,64,108. Assign dots evenly to groups in group-index order, remainder to earliest groups; within each group place consecutive row-major grid positions with width ceil(sqrt(groupCount)), subtract floor((width-1)/2) from x and floor((ceil(groupCount/width)-1)/2) from y. Uniform uses ceil(sqrt(totalCount)) columns at floor((col+0.5)*128/width), floor((row+0.5)*128/height). Layout offsets are (0,0),(3,5),(-4,2), all coordinates modulo128. Seam6 uses group6 then adds64 to x, then the layout offset; this makes one group cross the horizontal seam. Capture the appearance even when dots overlap. IDs are consecutive integers; the supplied group count is construction metadata, not image-derived organism count.

Shared renderer:128x128 RGB background[10,18,24], family palette[[103,218,184],[243,185,99],[172,146,235]]. Draw each dot as center plus four axial neighbors (radius1 Euclidean disk), wrap both axes; later particle ID overwrites earlier overlaps. Simulated positions become floor(128*wrappedCoordinate) integers, preserve particle IDs/families, sort by ID. The stored integer positions are the exact scorer/browser input; floating coordinates are not promised by this display export. Output raw RGB hash per frame plus deterministic PPM bytes for Pillow input; browser uses the same RGB raster expanded to RGBA ImageData and nearest-neighbor display. No browser re-simulation. CLIP uses pinned official processor config, RGB input, bicubic resize to224, center crop224 and official mean/std normalization; record all resolved settings.

Recipes use standalone Mulberry32 matching the existing particle stream algorithm, pinned seed0 test vector; no changes to old models. Every child consumes all11 draws regardless of clamping. Round bounded values to six decimals before validateRecipe. IDs are lineage IDs (preset-flocks etc.; initial-flocks-0 etc.; selected-0-0 etc.), not content IDs. Also hash canonical row-major recipe JSON. Record exact duplicates and reuse evaluation by content hash only if transparent; simpler permitted option is evaluate each lineage separately. Deduplicate late follow-up by recipe content hash, keeping winner priority then original preset order. Child preset is nominal ancestor metadata, never a behavior guarantee.

Eligibility: minimum population across all64 early frames>=60 and average census.meanSpeed across those64 frames>=0.0001 world-widths/tick. These are declared engineering filters, not a biological test. Zero eligible means stopped after initial pool; one eligible yields two selected-parent children and two control-parent children. With>=2, select top2, each two children. Selected generation uses seed91002, ranked parent order then child0/1. Untargeted controls select two distinct eligible parents by uniform sampling without replacement using seed91003 (or the sole parent when only one), then two children each with independent seed91004. Same mutation operator; overlaps with selected parents are retained, not redrawn. Thus follow-up has4+4 children when possible (20 total lineages including initial12). This balances opportunity but tiny one-generation comparisons still do not establish causal benefit.
