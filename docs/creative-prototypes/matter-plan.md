# Matter rain and burial: a counted aquarium

Candidate 4, a standalone creative prototype. Base is PR93 at ebd1692b; fetched main is 4730417a. The previous goal turn made concrete progress: Growing families is reviewed, tested, committed and open. This slice depends on that tip, with no merge or deployment. The user welcomes deliberately supplied mechanisms and wants interesting behavior; this is not a research-kernel amendment or an adaptation experiment.

## Why this slice

The particle/oases/seasons line already supplies renewable food and varies its location and timing. Calling that matter rain would repeat it. The boundary-field toy explicitly uses density proxies. Research `feedNutrient` is a logged intervention changing the baseline, while pond exchange preserves matter. Here actual counted material moves between a finite source, active water and irreversible sediment. Four matched tanks separate rain and burial. The intended visual subject is growing algae-like patches, moving growth fronts, falling detritus and sediment accumulation. That is a prediction, not a guaranteed result.

## Exact model contract

New `apps/lab/src/matter/model.ts`, no old model changes. Integer 64×48 grid, tile y*64+x. Wrap horizontally; top/bottom are closed boundaries. Directions 0 east, 1 south, 2 west, 3 north; off-grid vertical neighbors are absent. Three Uint32 pools per tile: N nutrient, B biomass, D detritus. No organism IDs, genes or inferred reproduction. A biomass patch is an image region, not an individual.

Modes are `closed`, `rain`, `burial`, `rain-burial`, corresponding to the two Boolean switches. All tanks retain the same initial reservoir even if rain is disabled. The world's full matter budget is `sum(N+B+D) + reservoir + sediment = initialTotal`. Rain moves reservoir→N; burial moves D→sediment. Internal changes only transfer between pools or locations. No matter is created or clipped away. Light is an externally supplied catalytic schedule; this is a matter ledger, not an energy conservation claim.

Seed is uint32, including zero; use Mulberry32 with unsigned result/4294967296. Initial N is `4 + floor(random()*9)` per tile in row-major order. Initial D is zero. Eight founders at x=8,24,40,56 and y=12,28 each place B=16. Draw one heading phase 0..3 per tile after all N draws. Phases are fixed for the run and identical in matched modes. Reservoir starts32768; sediment0. No other random draws after initialization. Initial total is at most69760, so every pool value, signed flux delta and aggregate is far below 32-bit overflow. Counts/cumulative transfer totals must remain nonnegative safe integers. Arrays are private and copied on input/output; fixtures must copy Node Buffer subclasses into base typed arrays.

### One tick, explicit phase ordering

Increment tick first. Each phase sees the previous phase's completed arrays, and uses synchronous old arrays inside that phase unless stated otherwise.

1. **Rain:** if enabled and tick%8==0, visit top-row x in rotating order `(floor(tick/8)-1+i)%64`, i=0..63. Move one reservoir unit into N at each visited tile while reservoir>0. Count actual imported units. Stop when empty. This is a finite drip, not uncounted replenishment.
2. **Nutrient mixing:** for each undirected east edge (including horizontal seam) and each valid south edge once, read old N. Transfer `floor(abs(Na-Nb)/4)` from higher to lower. Accumulate equal/opposite Int32 deltas then apply together. Each donor has at most four neighbors, and each outgoing transfer <=floor(oldN/4), so total outgoing<=oldN. Vertical boundaries have no edges. No clamp. Mixing conserves N exactly.
3. **Light and growth:** light center `floor(tick/10)%64`. A tile is lit iff y<36 and its minimum circular x-distance from the center is<=20. The band moves across the tank; all modes share it. For every tile with B>=4 and lit, transfer `min(1,N,max(0,64-B))` N→B. Count transferred units as growth. B>=64 does not grow. Growth is an engineered local conversion.
4. **Patch extension:** only when tick%12==0. Read post-growth B synchronously. Each tile with B>=24 proposes moving exactly4 B to its one neighbor with direction `(phase[tile]+floor(tick/12))%4`. Off-grid or targets whose old B!=0 are blocked and transfer nothing. Accepted proposals accumulate equal/opposite deltas; a target can receive from at most4 donors, hence new B<=16, while each donor loses4 at most and cannot also be an empty target. Apply together. Count moved biomass units and previously-empty target tiles colonized (unique targets, not proposal count). A new target never extends in the same phase. No N cost for moving existing biomass. This is supplied spatial propagation, not spontaneous creation.
5. **Mortality:** if tick%10==0, transfer1 B→D from each nonempty tile. Then on every tick, transfer all remaining B in(0,4) to D. Count actual units. Exact B=0 stays0; nothing can create biomass in a world with no biomass.
6. **Recycling:** if tick%8==0, transfer `min(1,D)` D→N per tile. Count actual recycled units.
7. **Settling:** from old post-recycling D, move `min(2,D)` one row downward for every tile above the bottom, using simultaneous deltas. Bottom D stays. Count units moved. No horizontal detritus motion.
8. **Burial:** if enabled and tick%4==0, visit all tiles with y>=40; transfer `min(1,D)` from each into sediment. Count actual buried units. Sediment never returns.
9. Record first tick with total B=0 as `extinctionTick` (null initially unless a fixture starts empty). **Do not freeze the tank**: nutrient, detritus, source and sediment continue moving after biomass extinction. Biomass remains zero without rescue. Sample observations on the cadence below.

Per-step biomass upper bound64: existing donors only lose; empty extension targets receive<=16; growth capped64. N/D bounded by initialTotal. No input mutation, hidden reseeding, stochastic survival or implicit material sources.

## Plan-review resolutions (authoritative before implementation)

Both Claude Sonnet High and Codex Sol6.1 High found the original conservation and bounds argument consistent. Their saved reviews identify genuine specification gaps and likely quiet behavior. The following decisions supersede earlier wording. These are deliberate pre-implementation creative choices, not post-pilot tuning.

### Deliberate dynamics changes

- Widen the moving light half-width from20 to24. Center remains floor(tick/10)%64 and y<36 remains lit-depth eligibility. Thus all eight original founder sites are initially illuminated, including x24 and x40 at the light boundary. The moving dark sector remains supplied environmental pressure. Keep founders B16 and the same total-matter bound.
- Slow recycling from every8 ticks to every24 ticks, still min(1,D) per tile. This gives falling material a greater chance to reach the burial zone before recycling. No promise of a burial effect: report zero transfer or identical outcomes honestly.
- Run mortality/threshold removal **before** patch extension (swap phases4 and5). Extension reads post-mortality B. Newly deposited B4 survives that tick; it is subject to the ordinary rules on subsequent ticks, without a special newborn exemption. Growth still precedes mortality. All donor/recipient and64-unit biomass bounds remain valid.
- Call N redistribution **threshold relaxation**. Differences below4 do not transfer, and synchronous integer updates can oscillate; do not call it fluid diffusion. Keep the specified signed simultaneous edge deltas. Add cumulative `relaxed` unit-moves. `spread` and `settled` also count unit-moves, not net pool conversions. `colonizedTiles` counts deposition events into previously empty targets (unique within a phase), not distinct sites ever visited or guaranteed persistence.
- Split mortality bookkeeping into `routineDecay` and `thresholdLoss`, with `mortality = routineDecay + thresholdLoss`. The material flow diagram can combine them as biomass→detritus. Dark rows y>=36 and burial rows y>=40 are intentional supplied zones, not emergent benthos. Darkness can prevent new deposits from expanding; no claim about real ecology follows.

### Accounting, history and observations

Retain initial N/B/D/reservoir stocks as immutable metadata in census/snapshot for every world/fixture. Every step, evidence and snapshot validator reconcile all identities, not merely the global residual:

- reservoir = initialReservoir - imported; sediment = buried.
- Ntotal = initialN + imported - growth + recycled.
- Btotal = initialB + growth - mortality.
- Dtotal = initialD + mortality - recycled - buried.
- After a positive step every B is0 or>=4, and <=64. Initial fixtures may contain1..3 for threshold tests.

Count components using B>=4 consistently with activeCells, including at fixture tick0. Increase history capacity to122, enough for tick0, all50-tick samples through6000, and one off-cadence extinction sample. Longer headless runs may drop old samples and report the count; initial stocks remain available independently. A fixture initially lacking biomass has extinctionTick0. Its clock and history still advance. The biomass-extinction banner says “material updates continue”; it does not promise ongoing movement. Water may become static. Report interval deltas in relaxed/settled unit-moves separately from biomass change.

Sampled biomass activity is endpoint change, not gross turnover. For the late window2000..3000, include all consecutive stored sample intervals whose from/to are inside that window, including an exact extinction sample. Because tick2000 and3000 are always sampled, interval durations sum to1000. Report `sum(meanAbsBChange)/1000` (units per tile per tick) and `sum(maskFlipFraction)/1000`. This can miss changes that cancel between samples. Also report exact counter differences over the same endpoints for growth, mortality, recycled, relaxed and settled to show turnover or transport despite a stable sampled picture. Never infer physical quiescence solely from zero biomass activity.

Run modes together per seed for direct paired comparisons. Record the first exact tick when physical N/B/D/reservoir/sediment differs from Closed, excluding mode metadata. Also record first burial-enabled divergence from its rain-matched control (Burial vs Closed; Rain+burial vs Rain). Null means no difference through the horizon. If all six burial-enabled worlds have buried0 and match their controls, label burial inert and retain that outcome without tuning. No “near-zero” threshold is invented.

The standard rain trajectory imports24000 units and retains8768 at tick3000; reservoir exhaustion occurs at4096. Report that the fixed pilot does **not** observe standard exhaustion or its aftermath. Rain import is a prescribed schedule shared by both rain arms, not an ecological result. The UI can reach6000, but its cap test and the small exhaustion fixture are not a substitute for a six-thousand-tick experimental batch.
