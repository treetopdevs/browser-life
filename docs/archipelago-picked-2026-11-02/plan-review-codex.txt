1. **P1 — Sparse input logs cannot satisfy the proposed stitch contract.** [PLAN.md:43](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:43) writes the canonical, potentially sparse input directly as `picks.jsonl`, then calls `picksConsistencyError`. That checker requires every boundary in `ponds.tsv` to appear in the log ([picks.ts:247](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/picks.ts:247)). The runner instead logs every applied boundary, including implicit choices ([runner.ts:1457](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/runner.ts:1457)). An in-memory probe with a pick at 5,000 and an implicit boundary at 10,000 returned `ponds.tsv has boundary 2, which picks.jsonl does not`. Parsed-entry equality also fails.

   **Fix:** distinguish the immutable sparse input from the complete applied history. Materialize the complete bundle `picks.jsonl`, and separately check that its explicit choices match the content-addressed input.

2. **P2 — The stitched manifest would retain only the last segment’s pick digest and counts.** The equality promise at [PLAN.md:45](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:45) lacks a metadata aggregation step. Each runner invocation initializes an empty `pickLog` and zero counts ([runner.ts:1133](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/runner.ts:1133)); stitching spreads the last manifest without replacing its `picks` block ([stitch.ts:877](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/stitch.ts:877)). This fails even with a complete input log: `picksDigest` hashes only the entries supplied to it ([picks.ts:273](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/picks.ts:273)).

   **Fix:** define segment-local metadata and recompute the stitched digest, boundary count, and recorded/live counts over the complete applied history. Test a final segment containing no pond boundary.

3. **P1 — The acceptance tests can certify islands that ignore the recorded choices.** [PLAN.md:111](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:111) requires equality against continuous replay, but never requires the chosen fixture to differ from implicit rule donors. That distinction matters: the existing GPU test explicitly proves that rule-picked and unpicked runs have identical hashes and pond files ([picked.ts:148](/Users/nicholas/develop/browser-life-archipelago-picked-runs/tests/deno/picked.ts:148)). Empty or rule-equivalent fixtures therefore prove transport and segmentation without proving application of external choices.

   **Fix:** pin valid, non-rule ordered donors at a segment end and in a later segment, plus an implicit boundary and an empty window. Assert exact donor assignments and a different immediate post-cycle state hash from the rule control. Require the real coordinator demo to exhibit one of those non-rule choices.

4. **P2 — Missing entries in a strict log escape the promised terminal failure path.** Creation checks at [PLAN.md:36](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:36) require entries to be within the run, but do not require complete coverage when `pickImplicit` is absent. An empty or incomplete strict log satisfies those stated checks. `picksPreflightError` rejects missing boundaries ([picks.ts:216](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/picks.ts:216)), and the runner throws an ordinary `Error` ([runner.ts:970](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/runner.ts:970)). Adding only `PickError` handling would miss it; the island propagates other errors and leaves ([island.ts:732](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/island.ts:732)), releasing unfinished work for another attempt.

   **Fix:** require complete boundary coverage at creation for strict logs, validate `pickImplicit` as true-or-absent, and add direct API tests for empty and missing-middle-boundary logs. Define terminal handling for deterministic fetched-log validation failures too.

5. **P2 — Upload validation requires a preset that the upload request does not identify.** [PLAN.md:34](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:34) specifies raw canonical log bytes at `PUT /api/pick-logs/:sha`, while requiring validation against “the preset’s pond period.” Neither the path nor those bytes identify a preset. The accepted presets have different periods: 1,000, 5,000, and 10,000 ([config.exs:125](/Users/nicholas/develop/browser-life-archipelago-picked-runs/apps/coordinator/config/config.exs:125)).

   **Fix:** separate context-free upload validation from experiment-context validation. At creation, validate the stored bytes against the selected preset, condition, duration, implicit policy, and exactly one condition/seed. Revalidate rather than treating existence in the shared blob store as proof of a valid pick log.

6. **P2 — Island-only GET authentication prevents the exporter from downloading the log.** [PLAN.md:31](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:31) makes GET island-authenticated, but [PLAN.md:42](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:42) requires `tools/stitch.ts` to fetch it. The exporter sends an administrator token or uses tokenless local administration; it supplies no island identity ([tools/stitch.ts:104](/Users/nicholas/develop/browser-life-archipelago-picked-runs/tools/stitch.ts:104)). `require_island` requires that identity ([api_controller.ex:438](/Users/nicholas/develop/browser-life-archipelago-picked-runs/apps/coordinator/lib/coordinator_web/controllers/api_controller.ex:438)).

   **Fix:** use the existing `require_island_or_admin` policy. Require hex64 validation on GET before calling `blob_path`, which itself performs no validation ([store.ex:56](/Users/nicholas/develop/browser-life-archipelago-picked-runs/apps/coordinator/lib/coordinator/store.ex:56)). Test administrator, island, unauthenticated, malformed-SHA, and tokenless-dev access explicitly.

7. **P2 — Cached exports can remain missing or corrupted pick logs.** The stitch changes and tests at [PLAN.md:41](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:41) cover downloading and writing the log, but omit `existing()`. That path checks `BUNDLE_FILES`, configured optional files, task binding, and pond structure before retaining an export ([tools/stitch.ts:289](/Users/nicholas/develop/browser-life-archipelago-picked-runs/tools/stitch.ts:289)); pick logs are in neither file list. Deleting the local pick log would therefore remain invisible to those checks. The planning source’s amendment 3 documents precisely this class of cached-export bypass ([archipelago-breed-2026-10-18.md:157](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-breed-2026-10-18.md:157)).

   **Fix:** extend cached-export validation for the chosen input/applied-log representation and aggregated metadata. Add repeat-export tests that delete or alter the log while coordinator fingerprints remain unchanged.

8. **P2 — The reused loader does not provide the refusal policy attributed to it.** [PLAN.md:49](/Users/nicholas/develop/browser-life-archipelago-picked-runs/docs/archipelago-picked-2026-11-02/PLAN.md:49) says `run.ts` refuses manifest lesions, feeds, and pressures. It accepts them: `labHistory` extracts those histories ([interventions.ts:348](/Users/nicholas/develop/browser-life-archipelago-picked-runs/packages/runner/src/interventions.ts:348)), and `run.ts` carries schedules and pressures into the replay spec ([tools/run.ts:411](/Users/nicholas/develop/browser-life-archipelago-picked-runs/tools/run.ts:411)). Consequently, extracting the loader unchanged does not establish the submit command’s restrictions. The advertised fallback fixtures are also unsuitable: v2 contains pressures ([fixture:76](/Users/nicholas/develop/browser-life-archipelago-picked-runs/tests/e2e/fixtures/pond-keeper-session-v2.json:76)); v3 contains a lesion ([fixture:76](/Users/nicholas/develop/browser-life-archipelago-picked-runs/tests/e2e/fixtures/pond-keeper-session-v3.json:76)); the original contains a lesion too ([fixture:86](/Users/nicholas/develop/browser-life-archipelago-picked-runs/tests/e2e/fixtures/pond-keeper-session.json:86)).

   **Fix:** make refusal an explicit submit-only policy over the loader’s returned history. Define how suns are handled as well, without silently dropping them. Add a clean picks-only fixture and preserve existing `run.ts` behavior.

The plan needs revision before implementation. Its reuse foundation is sound: the named existing facilities are present, the donor hook keys on absolute `pre.step`, and `(start, end]` ownership matches existing boundary semantics. The main blockers are the sparse-versus-applied-log contract and proof that islands actually apply non-rule picks; metadata, validation, authentication, and cached exports also need explicit treatment. The session export path is feasible. This was a read-only review with an in-memory helper probe; no files changed, and GPU, Playwright, and `mix precommit` gates were not run.
