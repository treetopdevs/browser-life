D6 — Monitor merge rule

A Sonnet 5.5 monitor polls open PRs. It merges with gh pr merge --merge (no branch deletion) when the PR is not draft, mergeable, every reported check succeeded or was skipped/neutral, and no unresolved review thread or comment makes a concrete ask. CodeRabbit "rate limited", "skipped" or summary-only output is not a finding. Stacked PRs merge base first; mergeability is re-read after each merge. Excluded: drafts, PR60 (do not merge until opening day), PR69 (scientific protocol needing a yes). PRs not opened by this run are merged only if their head has been unchanged for at least two hours, so a peer session mid-push is not raced. CI here runs only site-image and coordinator-image, so "green" means no reported check failed, not that every test ran; slice PRs record their local checks in the body. When CI fails or a comment is actionable, the monitor messages the PR's registered owner agent, or the coordinator when none is registered.
