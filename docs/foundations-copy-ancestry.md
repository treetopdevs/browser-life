# A1 copy and material ancestry diagnostic

Status: CPU controls implemented; natural replay and serial v2 have not run. This is a new exploratory protocol. It does not amend the completed serial-v1 experiment or its observer.

## Claims kept separate

The genome-copy color records which earlier **genome source cell** won the transport lottery. It is a genetic-copy trace, not a label for B, P, or E molecules and not an organism pedigree. A component's same-site overlap, its copied-genome source region, and its incoming material shares are reported independently. The simulator can mix material from several source cells while copying one genome, and later reaction can make new B from A. Material identity after reaction is therefore unavailable without an independently validated convention or tighter bounds; no endpoint inventory is called a material genealogy.

`tools/lib/foundation-local-flow.ts` reconstructs the unchanged flow displacement from a pre-step state only at source sites needed by a destination. `tools/lib/foundation-material-flow.ts` uses that displacement and the existing transport equations to report exact **pre-reaction** B/P/E shares and the lottery winner at that destination. `tools/lib/foundation-component-material.ts` joins those shares to one observed component and checks that the winner's neutral color appears after the step. A site that gains bound matter in reaction despite zero incoming bound mass has no lottery winner; its copy source remains unavailable instead of becoming a false replay failure. `postReactionBoundMinusIncomingBound` is a net local difference, not an assertion that all positive difference came from ambient A. `reactionMaterialOwnership` is explicitly unavailable. The CPU constructed controls compare local flow and transport against actual RefSim phases, including toroidal boundaries, motility, adhesion and a neutral controller. A GPU diagnostic must still match the unchanged full-world reference before these sidecar quantities are used on natural observations.

## First gate: source and step-0 geometry

`tools/foundation-copy-ancestry.ts` is CPU-only. It rechecks the authenticated source-1 cache, original bundle files, frozen extraction rule and catalog, decoded late checkpoint, and selected rank-zero component 53. It prepares the intact donor packet and two genotype substitutions on the **same exact packet cells** in the same garden. All three inoculated arms must have identical physical initial cells and exactly one census-eligible root under threshold 48/minimum mass 256. The empty garden must have none. This founder-on-evolved-geometry arm is a genotype intervention, not a control for natural founder morphology. The old serial-v1 founder disc had multiple eligible roots and remains an unchanged completed result. Failed or unavailable geometry is recorded before GPU work, never repaired after an outcome is seen.

The initial source-1 CPU preflight is `runs/foundations/copy-ancestry-preflight-source1-v1.json`. It is **post-baseline evidence despite its directory**. Subsequent artifacts go under `runs/foundations-next/`. That first report found one eligible root for each inoculated same-packet arm, zero for empty, and equal matter 2,101,020 in the inoculated arms. Revalidate all source/code identities when freezing a natural diagnostic; the first report is not a substitute for that later check.

## Natural debugging diagnostic, conditional on a GPU slot

The fixed debugging case is serial-v1 source-1 cycle-0 donor, seed 640010001. The previously observed births/fusion/fission around steps 150–250 motivated this diagnostic; it is intentionally outcome-informed and **not** a new biological replicate. A new plan must bind the exact serial-v1 plan/result hashes, source/cache/catalog/rule hashes, initial packet and state hash, selected helper code, device, cap and output path before execution. Reconstruct the old donor's exact initial state and compare it to the saved serial-v1 row.

Run an uncolored copy and a mutation-off lineage-color twin from step 0. Give each initially living cell an injective, valid color; no genotype parameter, controller weight, physical cell or random seed changes. Check physical cell channels, four-word genome head (mask only intentionally changed lineage words), and flux after **every** step through 250; compare full non-label genome and cumulative energy ledgers at each 25-step readback. Analyze all components at every 25-step census, including no-event, mixed, unknown, subeligible and extinct states. Audit exact pre-reaction shares for all components at the predeclared steps 175, 200 and 225, using consecutive pre/post snapshots. Record source-site material and genome-copy classifications separately. Capture the original 25-step assay observer and compare its prefix with the saved serial-v1 trace; continue the uncolored physical run to step 3000 and require the saved terminal physics hash. Run the unchanged original runner from the same exact initial state to 3000 and require the saved combined artifact hash and all six observation-file hashes. If any of these checks fail, the diagnostic is unauthenticated and cannot reinterpret serial-v1 events.

The first execution cap is 180 wall seconds, one source and one diagnostic twin, with no new M4 history. The two per-step snapshots read about 5.25 MiB total per step, roughly 1.3 GiB over 250 steps, plus periodic full-state reads; the separate original-runner replay adds 3000 physical steps. Actual timing and data volume must be measured, recorded and kept within the A1 one-hour cumulative allocation. Reserve a new artifact directory before GPU acquisition, retain partial diagnostics on a cap/error, and never mark a cap as biological absence. Root coordinates the single GPU slot.

## Recruitment gate for serial v2

A copy color applied after an event cannot assign its source. Serial-v2 recruitment must have uninterrupted copy-source coverage from placement or an authenticated pre-event start before **every** eligible event. A same-genotype component with a new tracker ID is insufficient. A color linked to the starting component is an initial-root genetic origin, not necessarily an immediate organism parent. Fix the first eligible separated component and tie rule before the pilot, retain all rejected/mixed/packet-invalid candidates, and never replace a chosen packet using later survival. Direct-root overlap fission remains a separate observation. A material-flow result is independent of this genetic-copy eligibility and may remain unavailable. Repeated packet propagation and organization built after transfer are separate endpoints, as specified in `docs/foundations-next-plan.md`.
