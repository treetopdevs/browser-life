Two-axis review of the diff between `HEAD` and a fixed point the user supplies:

- **Standards** — does the code conform to this repo's documented coding standards?
- **Spec** — does the code faithfully implement the originating issue / PRD / spec?

Both axes run as **parallel sub-agents** so they don't pollute each other's context, then this skill aggregates their findings.

The issue tracker should have been provided to you — run `/setup-matt-pocock-skills` if `docs/agents/issue-tracker.md` is missing.

## Process

### 1. Pin the fixed point

Whatever the user said is the fixed point — a commit SHA, branch name, tag, `main`, `HEAD~5`, etc. If they didn't specify one, ask for it.

Capture the diff command once: `git diff <fixed-point>...HEAD` (three-dot, so the comparison is against the merge-base). Also note the list of commits via `git log <fixed-point>..HEAD --oneline`.

Before going further, confirm the fixed point resolves (`git rev-parse <fixed-point>`) and the diff is non-empty. A bad ref or empty diff should fail here — not inside two parallel sub-agents.

### 2. Identify the spec source

Look for the originating spec, in this order:

1. Issue references in the commit messages (`#123`, `Closes #45`, GitLab `!67`, etc.) — fetch via the workflow in `docs/agents/issue-tracker.md`.
2. A path the user passed as an argument.
3. A PRD/spec file under `docs/`, `specs/`, or `.scratch/` matching the branch name or feature.
4. If nothing is found, ask the user where the spec is. If they say there isn't one, the **Spec** sub-agent will skip and report "no spec available".

### 3. Identify the standards sources

Anything in the repo that documents how code should be written, such as `CODING_STANDARDS.md` or `CONTRIBUTING.md`.

On top of whatever the repo documents, the Standards axis always carries the **smell baseline** below — a fixed set of Fowler code smells (_Refactoring_, ch.3) that applies even when a repo documents nothing. Two rules bind it:

- **The repo overrides.** A documented repo standard always wins; where it endorses something the baseline would flag, suppress the smell.
- **Always a judgement call.** Each smell is a labelled heuristic ("possible Feature Envy"), never a hard violation — and, like any standard here, skip anything tooling already enforces.

Each smell reads *what it is* → *how to fix*; match it against the diff:

- **Mysterious Name** — a function, variable, or type whose name doesn't reveal what it does or holds. → rename it; if no honest name comes, the design's murky.
- **Duplicated Code** — the same logic shape appears in more than one hunk or file in the change. → extract the shared shape, call it from both.
- **Feature Envy** — a method that reaches into another object's data more than its own. → move the method onto the data it envies.
- **Data Clumps** — the same few fields or params keep travelling together (a type wanting to be born). → bundle them into one type, pass that.
- **Primitive Obsession** — a primitive or string standing in for a domain concept that deserves its own type. → give the concept its own small type.
- **Repeated Switches** — the same `switch`/`if`-cascade on the same type recurs across the change. → replace with polymorphism, or one map both sites share.
- **Shotgun Surgery** — one logical change forces scattered edits across many files in the diff. → gather what changes together into one module.
- **Divergent Change** — one file or module is edited for several unrelated reasons. → split so each module changes for one reason.
- **Speculative Generality** — abstraction, parameters, or hooks added for needs the spec doesn't have. → delete it; inline back until a real need shows.
- **Message Chains** — long `a.b().c().d()` navigation the caller shouldn't depend on. → hide the walk behind one method on the first object.
- **Middle Man** — a class or function that mostly just delegates onward. → cut it, call the real target direct.
- **Refused Bequest** — a subclass or implementer that ignores or overrides most of what it inherits. → drop the inheritance, use composition.

Send a single message with two `Agent` tool calls. Use the `general-purpose` subagent for both.

**Standards sub-agent prompt** — include:

Present the two reports under `## Standards` and `## Spec` headings, verbatim or lightly cleaned. Do **not** merge or rerank findings — the two axes are deliberately separate (see _Why two axes_).

A change can pass one axis and fail the other:

- Code that follows every standard but implements the wrong thing → **Standards pass, Spec fail.**
- Code that does exactly what the issue asked but breaks the project's conventions → **Spec pass, Standards fail.**

Reporting them separately stops one axis from masking the other.

# I05 controller locality: evidence and go/no-go

Exploratory. CPU only (deterministic integer reference simulator and controller probe); no GPU evidence. Bounded to the tested genomes, the one-step operator, the 26,244-point probe grid and three short 16x16 tiny-world assays. Nothing here is a confirmation. Artifacts: `evidence.json` (sealed payload), `manifest.json` (source hashes, provenance), checked by `tools/locality/matrix.ts --check` / `--replay-check`. ## What was run

- Start genomes: hand-built generalist (positive control and measurement qualification, does not vote); M3 cluster 4 (sparse slot, passed the gate); M3 cluster 16 (dense slot, **failed** the viability gate: light-growth 924 permille, 19 permille under dark-persistence, so it is recorded as failed); M3 cluster 9 (dense slot, passed, used). Candidate order was fixed before data.
- Neighbourhood per genome: 94 edits (62 single-locus, 16 matched-magnitude multi-locus at total |delta| 24, 16 equal-slot-count secondary), all through the real `mutateInPlace`.
- Assays: light-growth, dark-persistence, dim-transfer; 2 paired seeds; horizon 200; 24 stratified assayed edits per M3 genome, 8 for the generalist. Neutral fixtures give exactly 0 deviation; sensitivity check passed (zeroing `w2 h1->photo` moved generalist light-growth by -2005 against tau 167).

| | generalist (control) | M3 c4 (sparse) | M3 c9 (dense) |
|---|---|---|---|
| edits that change the genome | 91/94 | 90/94 (2 unchanged, 2 boundary-clamped) | 91/94 (2, 1) |
| genuine edits silent on the probe | 51/91 | 33/90 | 11/91 |
| genuine edits undone by one operator step | 90/91 | 89/90 | 90/91 |
| assayed genuine edits viable | 8/8 | 24/24 | 24/24 |
| assayed edits improving a response by tau (A) | 2/8 | 1/24 | 1/24 |
| of A, harming another (C) / harming none (K) | 0 / 2 | 0 / 1 | 0 / 1 |
| median actuators moved by genuine w1/b1 edits (real vs degree-matched null) | 0 vs 0 | 1 vs 0 | 5.5 vs 7 |

Probe-level locality: most genuine edits move few actuators; the dense M3 genome 9 is far less silent (12% vs 37% for the sparse genome) but its w1/b1 edits move *fewer* actuators than the same weights placed at random (5.5 against 7), so its breadth looks like dense wiring rather than locus-specific entanglement. Viability is 100% of the assayed edits at a loose floor (500 permille of starting biomass); improvement is rare (1 of 24 per M3 genome, about 4%, inverse-probability-weighted 35 permille).

## Decision rule outcome

**Inconclusive (underpowered).** Both M3 genomes have A = 1, below the pre-stated minimum of 5 improving edits, so no collateral-loss or useful-neighbourhood statement is made. The rule's entanglement branch also could not fire on the probe half alone (c9 breadth does not exceed its null).

## Go/no-go for a separately versioned controller architecture (advisory, exploratory, bounded)

**No-go on this evidence; not a refutation.** Nothing measured here supports starting a modular-controller fork: the dense genome's wide actuator footprint is matched by its degree-matched null, there is no observed collateral loss (C = 0, because improvements are too few to say), and the sparse genome's edits are mostly local or silent. What the data do show is that useful edits are rare in this neighbourhood (about 4% of assayed edits), which is a statement about search efficiency on two genomes, not about representation. A later plan would need more improving edits (assay every genuine edit, longer or more varied scenarios) before any collateral-loss claim, and a fork would have to be parameter-, mutation-opportunity- and initial-quality-matched with search and transfer reported separately.

## Deviations from PLAN.md, and what is not done

- Calibration measured about 0.3 to 0.9 s per 200-step run, not the 19 ms/step in the plan. H was fixed at **200** (not 60-100) because at 80 steps the M3 genomes do not separate light from dark; H, tile, radius 6 and the gate floor 1000 / margin 250 were chosen on baselines and the generalist only. Dim scenario: light 20 + 60, nutrient 16.
- Assayed edits stay at 24 per M3 genome (not raised although runtime would allow more); this is the cause of the underpowered verdict. Duplicates and non-genuine edits are excluded from the draw.
- The worker pool was cut: serial runtime is about 75 s for the whole payload under Deno.
- Integer fluxes are not recorded; each run keeps initial and final B, P, E (first seed of light-growth in the row) and the replay-check compares final B, P, E, A, C for fixtures only.
- Multi-locus vs single-locus clean share is computed on assayed genuine edits only (multi 1/6, single magnitude 24: 0/8 per M3 genome).
- Image checks not run (no image built). No GPU evidence.
- Under vitest's node transform the replay is an order of magnitude slower than under Deno, so the replay test runs `--replay-check` as a Deno subprocess.

## 1. Bounded question

For three chosen viable starting controllers, is the one-step mutation neighbourhood of the existing 10-8-8 int8 controller (a) mostly silent, clamped or harmful, (b) broad in the actuators and sensors each edit moves (entangled), and (c) where edits do improve one independently assayed capability, do they usually cost another? Answer is bounded to those genomes, that operator, those grids and those short scenarios. It does not diagnose "the controller" in general, and it does not transfer the FER (deep representation) argument to this controller: that is an analogy under test.

Out of scope by decision: any controller-layout change, modular variant, search/evolution run, large `runs/` input, GPU evidence.

## 2. What is built (one PR)

1. **Evidence fixture with a negative case.** Known-history controllers built by exact algebra, not searched:
   - *hidden-unit permutation* (swap hidden units a and b: permute `W1` columns, `b1`, `W2` rows). Function is identical on every input, yet many bytes differ. Fools the naive metrics "bytes changed" and "weight-space distance as edit size". Expected: probe outputs byte-identical, expression `probe-silent`/identical, physical assay identical (checked, not assumed).
   - *dead-hidden edit* (edit an incoming weight of a hidden unit whose `W2` row is all zero): a nonzero edit with zero function change.
   - *clamp edit* (push a byte at +-127 further out): minted as an edit, genotype unchanged. Fools "number of edits applied".
   - *shuffled sensor labels* (permute `W1` input rows): a genuinely different controller, labelled a negative fixture, not an ecological intervention. No breadth invariant is promised: the `PROBE_AXES` sensors have different supports, cardinalities and signs, so permuting rows changes the sampled input distribution (a swap of light and polymer rows on the generalist with photo bias -60 and `w2 h1->photo +6` moves actuator breadth from one to zero). Expected values are fixture-specific tables computed once and pinned in the test. Sensor-attribution bookkeeping (edit at `w1 in=k` attributes to sensor k, and to sensor pi(k) after the shuffle) is tested separately as pure relabelling.
   - *hand-built generalist* (`generalistGenome`, where each weight's role is documented): a positive fixture with expected localisation (e.g. `w2 h1->photo` moves photo only, within the light sensor's reach).
2. **Mutation neighbourhood generator** (pure, integer, counter-PRNG keyed on a stated salt, genome id and index; no `Math.random`). Reuses `mutateInPlace` from `@bl/sim-ref` as the only editor (so clamping and the sigma `>>2` rule are the real operator's), `locusOf`/`slotValue` from `@bl/lineage` for labels and before/after values, and `probeGenome`/`expressionOf` for expression. Per starting genome:
   - Selection of loci, signs and draw indices is a pure function of (salt, genome id, family, index) frozen before any probe or assay outcome is computed. Mandatory engineered fixtures are separate rows (`family: fixture`) and are never in any mutation-rate numerator or denominator.
   - single-locus: a fixed stratified sample of slots per kind (`w1` 10, `b1` 4, `w2` 10, `b2` 4, plus `mu`, `sigma`, `gain`), each at signed magnitudes 6 and 24 (24 = default `mutStep`);
   - matched-magnitude multi-locus: k = 2 and k = 4 distinct controller slots with per-slot deltas of 12 and 6, so the total |delta| equals the 24 single edit (8 draws each, fixed signs by the draw); a second matching by equal slot count (k edits of 24) is also emitted as a labelled secondary family so magnitude and breadth are not confounded;
   - every edit records three deltas per slot: the **operator delta** requested of `mutateInPlace` (delta = `deltaRnd % (2*mutStep+1) - mutStep`, reachable for any value in [-mutStep, mutStep] by choosing `deltaRnd`), the **expected slot delta** after the operator's own scaling (sigma uses `delta>>2`, minimum magnitude 1, so +6 gives +1 and -6 gives -2; this scaling is not clamping), and the **applied delta** read from before/after words. Classes: `unchanged` (applied 0), `boundary-clamped` (applied differs from expected slot delta because a bound bit, nonzero applied), `genuine` (applied equals expected, nonzero). Requested and realised L1 magnitude are both recorded for multi-locus edits. The genome hash and the one-step undo are recorded: undo applies the negated **operator** delta with the same operator and compares to the original words; reversibility is reported per kind and is not expected for sigma or boundary-clamped bytes;
   - edits that give the same genome words as another edit or the baseline are deduplicated for physical assay (keyed by genome hash) but kept as rows.
3. **Controller response descriptors on a predefined sensor grid.** The existing `PROBE_AXES` grid (26,244 points, 10 sensors, 8 actuators) is the predefined grid; no new grid. Per edit, from before/after `Probe.outs`: per-actuator changed **counts** (out of the derived grid size), integer permille computed from counts, and max delta in integer units. `expressionOf` returns fractional shares (e.g. 0.667) and `Probe` carries fractional summaries (`meanOut`, `regimeEntropy`), so the locality code computes its own integer counts from `Probe.outs` and passes only the `expression` class through; fractional probe summaries never enter the payload, **actuator breadth** (number of actuators moved above a stated floor, plus the integer participation count from per-actuator max deltas). The grid size is derived from `PROBE_AXES` (3^8 x 2^2 = 26,244 points, 8 actuators, 209,952 output values per probe), never hard-coded, and is used in tests and denominators, **sensor reach** (number of sensors whose level changes the response: for each sensor axis, whether the delta table differs across that axis's levels), and a **structural-reach upper bound** (actuators and sensors topologically reachable through nonzero weights from the edited slot; saturation can suppress reachable outputs but cannot move disconnected ones, so realised <= structural is a sanity check, never a gate target). What separates "dense wiring of this founder" from "locus-specific entanglement" is a **degree-matched null**: the same genome with its nonzero W1/W2 magnitudes placed at shuffled positions (same count of nonzero weights per layer), edited by the same neighbourhood, giving a breadth distribution that dense wiring alone would produce; the gate compares the real genome to that null. Descriptors are mechanistic, not fitness, and say nothing about inputs outside the grid.
4. **Small CPU physical assays** (`RefSim`, tiny worlds), independent capabilities measured separately and never summed:
   These are **environmental biomass responses**, not independent capabilities: all three score terminal bound biomass `B`, which respiration (`B->C+E`) and construction (`B->P`) can lower even when useful, and founder geometry, initial energy and short-horizon depletion couple them. The record keeps initial and final `B`, `P`, `E` and the relevant integer fluxes per run, and the readouts say "biomass response" and never "capability" without that caveat.
   - `light-growth` (standard setting): founder disc in a small tile under standard light and nutrient; outcome = bound biomass `B` after H steps relative to initial, integer ratio in permille;
   - `dark-persistence`: same with light removed (config `lightBase`/`lightAmp` overrides; no schema change); outcome = biomass retained (permille);
   - `dim-transfer` (one alternative setting, for transfer): lower light and nutrient; outcome as `light-growth`.
   Tile 16x16 only (`validateConfig` needs dimensions divisible by eight, so 12x12 is invalid and schema validation is not changed), `kernelRadius` 3, `mutRate` 0 so the assay measures the controller change and not further mutation, H of order 60-100 steps; exact values fixed at calibration (section 6) and then frozen in code before the main run. Measured on this checkout: about 19 ms per step at 16x16/r3. **Budget (frozen before the main run):** assayed edits per M3 genome = 24, scenarios = 3, paired seeds = 2, H = 80 gives 24x3x2x80x0.019 = about 220 s per M3 genome, plus the baselines, fixtures (about 10 runs each) and a qualification-only generalist (8 edits, about 70 s): about 9 minutes serial, about 3 minutes with 4 Deno workers (deterministic job ids, results ordered by id, worker count not in the payload). If calibration projects more than 10 serial minutes, a stated ladder applies in order: H to 60, then assayed edits per M3 genome to 16; seeds stay 2 and scenarios stay 3. If it still exceeds the budget, the physical half is reported measurement-limited rather than thinned further. The subset is a **stratified draw frozen before any outcome**: strata = locus kind (w1, b1, w2, b2, physics) x family (single 6, single 24, multi k=2, multi k=4), fixed per-stratum allocation, draw by the counter PRNG; inclusion probabilities are recorded and the physical readouts are reported as **assayed-subset rates** next to inverse-probability-weighted neighbourhood estimates; they are never described as rates over all ~156 generated edits. The subset list is recorded in the manifest. Viability gate (stated before data): the unmutated baseline must have `light-growth` above a stated floor and `light-growth` must exceed `dark-persistence` by a stated margin on the same genome. The floor, margin, H and tile are frozen from the **generalist** and neutral-control behaviour only, then applied unchanged to the M3 genomes. A candidate that fails is retained in the manifest as failed (never silently dropped); branch logic is in section 3.
   - Noise and sensitivity controls: seed shift is sensitivity to initialisation and stochastic rounding (founder biomass/energy init and reaction rounding depend on the seed even with `mutRate` 0), not a calibrated noise bound. Every mutant is therefore run **paired** with the baseline on the same two frozen seeds, and the endpoint deviation is the paired difference averaged over the seeds. Neutral controls (hidden-permutation, dead-hidden, boundary-clamped, unchanged) must give a paired deviation of **exactly 0** (same genome function, same seed, deterministic sim); a nonzero value is a bug, not noise. Tau for "changed", per endpoint, = max(5% of the baseline value, 3x the largest cross-seed spread of the baseline itself on the frozen seeds); tau is computed from the baseline and the generalist only, never from the mutants. Sensitivity failure: if a known controller perturbation on the generalist (zeroing `w2 h1->photo`, which must remove light growth) does not move `light-growth` by more than tau, the physical half is declared measurement-limited and no bottleneck recommendation is made.
5. **Readouts** (rows keyed by starting genome, locus kind, locus, family, magnitude): fraction of genuine edits that are viable (all three biomass responses above floor), fraction improving at least one by tau, collateral loss (another response worse by tau), clean improvement (improves one, harms none), reversibility, transfer (does a `light-growth` improvement persist in `dim-transfer`), actuator breadth and sensor reach per edit, realised-over-structural reach. Stratified by locus kind and starting genome; no pooling of genomes into one rate without the per-genome rows beside it. Readouts are **finite-panel counts with denominators**, no nominal binomial interval: loci and signs are reused across families, multi-locus edits share constituents and duplicate genotypes stay as rows, so exact-coverage claims do not hold (an ideal independent 0/40 would still only bound the rate at about 8.8%, which is not evidence for a rate under 2%). The payload holds integers only (counts, denominators, permille); the page and evidence say so, and that the unit is the edit within a genome, describing the sampled neighbourhood, not a population of genomes.
6. **Evidence JSON + manifest + `--check`**, and a **mutation-effect matrix view** (local prototype page).
7. **Written go/no-go** (`docs/controller-locality-2026-11-01/EVIDENCE.md`), labelled exploratory and bounded.

## 7. Decision rule (stated before data; recorded in evidence)

Computed per qualifying M3 genome (at most two), reported side by side and never pooled; the generalist does not vote. Let A = number of assayed genuine edits that improve at least one biomass response by tau, C = those among A that also lose another by tau, K = those among A with no loss (clean).
- **Underpowered:** if A < 5 for a genome, no collateral or useful-neighbourhood statement is made for it (counts reported; the fixture sensitivity check still applies). This closes the 0 >= 0 hole in which zero improvements would satisfy a collateral rule.
- **Broadly useful (prefer better search and ecological incentives, no architecture change):** for both M3 genomes with A >= 5, K/A >= 50% and K is at least 10% of the assayed genuine edits, and multi-locus edits are not worse than single-locus at matched requested magnitude, meaning the multi-locus clean-improvement share is no more than 5 percentage points below the single-locus share on the shared strata (stated statistic, stated allowed deficit).
- **Entanglement signal (a representation fork is worth a separately versioned study):** for both M3 genomes with A >= 5: C/A >= 50%; and the median actuator breadth of genuine `w1`/`b1` edits is at least 3 actuators and exceeds the median breadth of the degree-matched null for that genome by at least 1 actuator. Structural reach is reported alongside as an upper-bound sanity check only.
- If the two genomes disagree, or either is underpowered: **inconclusive**, no architecture claim. Failed sensitivity check or no qualifying genome: **measurement-limited**. A single-genome verdict (section 3) can only be inconclusive or measurement-limited.
Either of the first two outcomes is a statement about these genomes, this operator, this grid and these short biomass-response scenarios, and says what a modular variant would still have to show (parameter-matched, mutation-opportunity-matched, initial-quality-matched, direct search and transfer reported separately). The EVIDENCE.md "go/no-go" is advisory for a later plan, not authorisation. All thresholds are exploratory, were set before data, and are not tuned afterwards.

## 9. Non-goals and limits

- No modular controller, no layout change, no new genome encoding, no search or evolution experiment, no GPU, no new physics, no `RULE_VERSION` change, no optional config key.
- The probe grid is canonical, not the inputs a lineage meets: "no effect on the grid" is not "no effect in the ecology" (the physical assays catch some of that, only for three short scenarios).
- Tiny CPU worlds are not the M3 evaluation (64-cell tiles, thousands of steps, regeneration after lesion, GPU). Capabilities here are growth and persistence over a short horizon in small worlds; they are not survival, lesion regeneration or ecological fitness, and results are not a statement about those.
- Edits sampled once from a fixed neighbourhood on three genomes: no population claim; no claim that evolved lineages behave likewise; edit-level intervals describe the sample.
- One-step neighbourhood only: no epistasis beyond the matched multi-locus families, no walks.
- Locality is a mechanistic descriptor, not fitness; thresholds are exploratory and set before data; the neighbourhood is not tuned after seeing results.
- Evidence payload contains no timing or platform (those go in a non-replayed provenance block of the manifest). Floating point stays out of the payload; counts, denominators and permille only, no intervals.
- Not deployed: the page is built by Vite but removed from the site image and 404 at the edge; no push, PR or commit at the PLAN stage.
50-Effort bands are planning estimates for a smallest credible prototype, not delivery promises: **S** roughly 2–4 engineering days; **M** 1–2 weeks; **L** 3–6+ weeks. They exclude scientific run time, review and resolving failed measurement gates. Priority reflects expected information gained per implementation effort, not likelihood of a positive biological result.

Run multiple independent search histories; the search history is the unit of replication, not its hundreds of correlated archive members. Report both simulator evaluations and wall time/model cost.

Include recoloured/re-rendered copies of the same trajectory, repeated trajectories, static patterns and noise as embedding controls. Use a fixed audit panel to measure semantic-score drift.

If visual breadth rises without capability breadth, ship it as a discovery gallery and stop claiming scientific improvement. Existing held-out ecology/multilevel metrics remain excluded from search unless a separately registered experiment changes their role. **Deliverable:** archive schema, comparison runner, replay gallery and audited selection ledger.

85-### I02 — A naturalist that predicts interventions
86-
87-**Question.** Can a model identify a causal mechanism well enough to predict an intervention, beyond what numerical baselines predict? **Sources:** [ASAL](https://pub.sakana.ai/asal/), [FER](https://arxiv.org/abs/2505.11581).
88-
89-**Experience.** A field note says, “I expect this patch to lose its advantage if signal is disabled,” with a confidence and a proposed paired replay. The notebook subsequently records whether the prediction survived. Observations, hypotheses and measured outcomes are visibly distinct.
90-
91-**Implementation.** Extend the existing naturalist bench and suggestion pipeline. Its input is a fixed evidence envelope: registered frame samples, census series, configuration and an allowed intervention menu. Its output is structured data containing subject/time, predicted direction, readout, intervention, confidence and an abstention option. A host validator permits only predefined data operations. Use the discovery campaign format where compatible; the current CPU case runner is not automatically a general naturalist benchmark.

Evaluate on already-known mechanism fixtures first, then unfamiliar cases.

Equalise available evidence and intervention budget. An expensive model must improve decisions, not merely write more interesting descriptions.

Do not extend existing neutral-bell calibration to new worlds without recalibration. **Deliverable:** prediction/outcome JSONL, comparison table and a notebook view of failed as well as successful predictions.

99-### I03 — Historical-opponent ecology
100-
101-**Question.** Does later evolution produce broader competitive ability, specialised counter-strategies, or mere replacement? **Sources:** [Digital Red Queen](https://arxiv.org/abs/2601.03335), [Core War](https://corewar.co.uk/).
102-
103-**Implementation.** Archive genotypes or explicitly defined population samples at fixed times, then compete them against a frozen panel spanning ancestral and intermediate opponents. Reuse mutation replay and discovery tooling. Begin with genome-only, standard-inoculum common gardens; test ecological context separately. Moving a whole patch also moves stored resources, partners and developmental state, so that is a different experiment.
104-
105-**Experiment.** Use reciprocal positions and starting ratios, mutation-off assays, independent source histories, identical budgets and a genotype-neutral two-label control. Start from a small panel of known distinct strategies to establish assay sensitivity. Include isolated-growth performance so “wins” caused solely by general vigour are distinguishable from matchup-specific advantages. Report diversity independently from mean win rate. Account for synthesis versus lottery relabelling where the exact observer permits it; label unresolved attribution rather than claiming predation.
108-
109-**Advance/stop.** Do not run a long tournament if both candidates routinely hit the extinction floor. First fix the assay or report it uninformative. A positive result establishes competitive change in the tested environment, not organism reproduction or open-endedness. **Deliverable:** replayable matchup bundles and an interactive time-versus-opponent matrix. No predation rule is required for the first test.

136-

139-**Implementation.** Extend the existing discovery design's conditioned-field experiments. Start with polymer, chemical fields and current transport rules. 301-### ASAL — Kumar et al. (2024; arXiv v2 May 2025)
302-[Paper](https://arxiv.org/html/2412.17799v2), [user-supplied abstract](https://arxiv.org/abs/2412.17799), [project and demos](https://pub.sakana.ai/asal/).
303-Uses foundation-model image representations for three tasks: text-target search, temporal novelty, and illumination across simulations. Tested substrates include Boids, Particle Life, life-like cellular automata, Lenia and NCA. Target search uses CLIP with Sep-CMA-ES; illumination uses a genetic search retaining diverse simulations. Temporal novelty minimizes similarity to earlier embedded frames; illumination measures nearest-neighbor difference across simulations. Its finite observation windows and representation-relative novelty do not establish indefinite evolution, causal individuality, heredity or ecological closure. The project page supplies useful demos but is not independent corroboration of the paper.

305-### Digital Red Queen — Kumar et al. (2026)
306-[Paper](https://arxiv.org/html/2601.03335v1), [abstract](https://arxiv.org/abs/2601.03335), [project explanation](https://sakana.ai/drq/).
307-Evolves Redcode programs against a growing archive of previous champions, using LLM mutation within MAP-Elites. Descriptors are spawned processes and memory coverage. Held-out human warriors assess generality. Across 96 runs, generality increases while behavioral diversity across histories decreases and within-history change slows. Limited-history comparisons study cycling. Removing the diversity archive hurts optimization. Crucial distinction: the paper finds competitive robustness and convergence, not indefinitely expanding ecological diversity. LLM proposals import an external prior; they are not mutations arising spontaneously inside the simulated world. A growing opponent archive also dilutes each new opponent's effect.

330-

333-Title: *Assembly theory explains and quantifies selection and evolution* (Sharma, Czégel, Lachmann, Kempes, Walker, Cronin, 2023).
334-
335-The paper combines an object's shortest recursive construction path (assembly index) with copy abundance. Its ensemble measure is `A = sum_i exp(a_i) (n_i - 1) / N_T`. The authors model discovery and production in assembly spaces; crucially their selection model specifies differential reuse rather than modelling every functional mechanism. Application requires physically meaningful primitives and combination operations. This suggests measuring repeated construction rather than treating visual intricacy or compression as evidence of life. It does not establish that any compression measure, arbitrary image motif count, or high index proves Darwinian evolution. Nature's direct fetch redirected to inaccessible authorization; the University of Glasgow PDF supplied the paper.
