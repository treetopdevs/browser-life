# What to grow next

## A research programme for browser-life

**1 November 2026 · Planning, not experimental results.** Human edition: [report.html](report.html). Agent edition: [report.md](report.md). Repository inspected at `c975f83492a50d2156faf5f3d136ea284ff2f9e5`, with existing unrelated local changes preserved. Source access was checked during this research; inaccessible material is explicitly identified below. No simulations, model API jobs, deployments, or changes to physics were performed.

The best next move is a **museum of useful possibilities**: an archive of distinct, replayable behaviours, followed by interventions that establish what causes them. Add a historical-opponent assay to distinguish improvement from turnover. Only then spend engineering effort on a different substrate or a more expressive genome.

This recommendation combines ASAL's learned search interface, MAP-Elites' preservation of alternatives, Stanley and Lehman's stepping stones, and Digital Red Queen's historical opponents. It also addresses a particular local problem: the repository's own foundations work found that visible change, lineage births, recovery, and reproduction cannot be treated as interchangeable evidence.

### Three things to start

1. **I01 — Behaviour atlas.** Extend the existing archive with carefully separated search descriptors and independent capability tests. Preserve stepping stones instead of selecting only one impressive survivor.
2. **I02 — Causal naturalist.** Let an observer nominate an experiment and earn credibility by predicting its result. Keep attractive pictures and biological evidence as separate outputs.
3. **I03 — Historical-opponent ecology.** Reuse competition and transfer machinery to ask whether later populations actually improve against a frozen panel, or merely cycle through matchups.

### Three things to resist

- “More novelty” as a single objective. Randomness, flicker, rendering changes and label churn can all increase apparent novelty.
- Another injury-selection sweep before resolving existing recovery-assay questions. The October 24 recovery programme already has a selected parent–mutant candidate and a staged plan.
- Treating external optimisation as autonomous evolution. A trained NCA, an LLM-written warrior and a breeder-selected pond can be excellent experiments, but the source of design must stay visible.

## Reading corrections and evidence boundaries

The item called **“FEP paper”** links to **Questioning Representational Optimism in Deep Learning: The Fractured Entangled Representation Hypothesis**. This is FER, not the free-energy principle. It motivates representation and controller-transfer tests here; this report does not derive an active-inference ecology from the mistaken label. [FER paper](https://arxiv.org/abs/2505.11581)

Digital Red Queen reports increasing generality under its tests, alongside convergence and reduced behavioural diversity. Its lesson is to measure arms-race dynamics and generalisation separately from repertoire growth. It does not establish perpetual open-ended evolution. [DRQ paper](https://arxiv.org/abs/2601.03335)

ASAL supplies externally learned criteria for searching simulations. Growing NCA supplies externally trained local rules. Assembly theory supplies a proposed account of selection through construction and multiplicity. None establishes that this repository's inferred components are reproducing individuals. Claims in the source dossier below are distinguished from the experiments proposed here.

The two separately linked videos remain full-content access gaps. The RESCRIPT interview transcript was recovered through the browser; its short excerpts from other interviews do not close those gaps. Accessible primary papers support technical claims. The transcript also explicitly distinguishes a memorised developmental movie from a causal evolutionary sequence—a useful warning for every proposed gallery. [Interview transcript](https://app.rescript.info/public/share/Qfv3T0EVzqOXL_CYYeRr9Blv8HnNm4JsXBh7ByFjJbc)

## Detailed idea plans

### I01 — Behaviour atlas and stepping stones

**Question.** Does retaining diverse viable behaviours expose transferable capabilities that a recovery-focused archive misses? **Sources:** [MAP-Elites](https://arxiv.org/abs/1504.04909), [ASAL](https://arxiv.org/abs/2412.17799), [Why Greatness Cannot Be Planned](https://link.springer.com/book/10.1007/978-3-319-15524-1).

**Experience.** A browsable cabinet of short replay clips: moving, resting, repairing, following, building, coexisting. Each specimen has a reproducible starting state, an ancestry of *search proposals*, and a card saying which tests it has actually passed. People can retain an unusual specimen without declaring it fitter.

**Smallest implementation.** Add an opt-in archive adapter beside the existing mass/speed map. Start with two predeclared physical descriptors, such as centre-of-mass displacement and temporal occupancy persistence, whose definitions are valid even when component identity is ambiguous. Evaluate an additional learned trajectory embedding as a separate arm, rather than silently replacing the descriptors. Fix rendering, frame cadence, encoder version and preprocessing. Store all accepted candidates and proposal ancestry, not just current elites. Reuse bootstrap evaluation and replay bundles; do not put model calls inside `step()`.

**Experiment.** Equal evaluation budgets for random viable sampling, the existing archive, a physical-descriptor archive and an embedding archive. Use the same starting candidate pool. Select on screening seeds; compare on fresh environments and seeds using capabilities withheld from every selector. Run multiple independent search histories; the search history is the unit of replication, not its hundreds of correlated archive members. Report both simulator evaluations and wall time/model cost.

**Readouts and controls.** Held-out capability coverage, archive retention, failure/extinction, duplicate-genotype rate, and transfer. A new visual bin is not a new capability. Include recoloured/re-rendered copies of the same trajectory, repeated trajectories, static patterns and noise as embedding controls. Use a fixed audit panel to measure semantic-score drift.

**Advance/stop.** Advance only if a predefined improvement in held-out coverage survives fresh searches and render perturbations. If visual breadth rises without capability breadth, ship it as a discovery gallery and stop claiming scientific improvement. Existing held-out ecology/multilevel metrics remain excluded from search unless a separately registered experiment changes their role. **Deliverable:** archive schema, comparison runner, replay gallery and audited selection ledger.

### I02 — A naturalist that predicts interventions

**Question.** Can a model identify a causal mechanism well enough to predict an intervention, beyond what numerical baselines predict? **Sources:** [ASAL](https://pub.sakana.ai/asal/), [FER](https://arxiv.org/abs/2505.11581).

**Experience.** A field note says, “I expect this patch to lose its advantage if signal is disabled,” with a confidence and a proposed paired replay. The notebook subsequently records whether the prediction survived. Observations, hypotheses and measured outcomes are visibly distinct.

**Implementation.** Extend the existing naturalist bench and suggestion pipeline. Its input is a fixed evidence envelope: registered frame samples, census series, configuration and an allowed intervention menu. Its output is structured data containing subject/time, predicted direction, readout, intervention, confidence and an abstention option. A host validator permits only predefined data operations. Use the discovery campaign format where compatible; the current CPU case runner is not automatically a general naturalist benchmark.

**Experiment.** Blind the proposer to intervention outcomes. Compare numeric-only, video-only, combined inputs, a fixed rule proposer and shuffled evidence on identical cases. Split whole source histories between development and final testing. Do not let multiple windows from the same run leak across splits. Evaluate on already-known mechanism fixtures first, then unfamiliar cases.

**Readouts.** Proper probability scoring (Brier score), directional accuracy, abstention/coverage, invalid proposals, outcome effect size, cost per useful experiment and counterfactual agreement. Equalise available evidence and intervention budget. An expensive model must improve decisions, not merely write more interesting descriptions.

**Advance/stop.** Require better prospective prediction than the strongest simple baseline and stable calibration on held-out histories. If it only captions, retain a clearly labelled narration feature. Do not extend existing neutral-bell calibration to new worlds without recalibration. **Deliverable:** prediction/outcome JSONL, comparison table and a notebook view of failed as well as successful predictions.

### I03 — Historical-opponent ecology

**Question.** Does later evolution produce broader competitive ability, specialised counter-strategies, or mere replacement? **Sources:** [Digital Red Queen](https://arxiv.org/abs/2601.03335), [Core War](https://corewar.co.uk/).

**Implementation.** Archive genotypes or explicitly defined population samples at fixed times, then compete them against a frozen panel spanning ancestral and intermediate opponents. Reuse mutation replay and discovery tooling. Begin with genome-only, standard-inoculum common gardens; test ecological context separately. Moving a whole patch also moves stored resources, partners and developmental state, so that is a different experiment.

**Experiment.** Use reciprocal positions and starting ratios, mutation-off assays, independent source histories, identical budgets and a genotype-neutral two-label control. Start from a small panel of known distinct strategies to establish assay sensitivity. Include isolated-growth performance so “wins” caused solely by general vigour are distinguishable from matchup-specific advantages. If evolving against an archive is later tested, compare recent-only, fixed-panel and historical-mixture opponents at matched compute.

**Readouts.** Full pairwise payoff matrices with uncertainty, invasion from rare, extinction, generality on opponents withheld from training, and cycles such as A beats B, B beats C, C beats A. Report diversity independently from mean win rate. Account for synthesis versus lottery relabelling where the exact observer permits it; label unresolved attribution rather than claiming predation.

**Advance/stop.** Do not run a long tournament if both candidates routinely hit the extinction floor. First fix the assay or report it uninformative. A positive result establishes competitive change in the tested environment, not organism reproduction or open-endedness. **Deliverable:** replayable matchup bundles and an interactive time-versus-opponent matrix. No predation rule is required for the first test.

### I04 — Repair across unfamiliar wounds

**Question.** Is a recovery advantage specific to one lesion geometry, or does it transfer to unseen damage? **Sources:** [Growing NCA](https://distill.pub/2020/growing-ca/), [Lenia](https://arxiv.org/abs/1812.05433).

**Implementation.** Continue the existing October 24 measurement and parent–mutant programme first. That plan already fixes its candidate and staged decision; this idea is a separately recorded follow-up after its outcome, not permission to replace it. Add replayable damage masks and a secondary repair-characterisation battery around the current evaluator.

**Experiment.** Match removed bound mass across contiguous, dispersed and asymmetric damage, rather than equating radius with injury severity. Include sham intervention, matched intact worlds, mutation-off trials, and a background-regrowth control. Fix damage times before outcomes; use fresh challenge geometries for final transfer. Account for the destination of removed matter and energy through the existing lesion semantics. A wound is an external intervention, not autonomous ecology.

**Readouts.** Recovery time, retained-component continuity under the operational tracker, spatial organisation, resumed function, and mass. Report whole-tile replenishment separately from remnant recovery; a film that fills space can pass a mass score without repairing the original organisation. Censored recovery times and extinct trials remain in the analysis.

**Advance/stop.** Advance from reliable recovery measurement to transfer, then to a selection experiment only if both are informative. A failure of identity tracking is a measurement-limited result. A successful engineered NCA (I10) is a positive control for an observer, not proof that current ecology can evolve repair. **Deliverable:** damage-mask fixtures, a mass-severity audit, and side-by-side repair trajectories. It should explain existing recovery results before generating another wound sweep.

### I05 — Controller locality and useful mutations

**Question.** Are useful edits rare because the local neural controller entangles unrelated behaviours? **Sources:** [FER](https://arxiv.org/abs/2505.11581), [AutoML-Zero](https://arxiv.org/abs/2003.03384).

**Implementation.** Start without new physics: use `probeGenome`, genotype keys and exact mutation/reversion to map perturbations onto controller outputs and independently assayed capabilities. Separate unchanged/clamped edits from genuine genotype changes. The FER hypothesis concerns deep learned representations; its application to a small evolved fixed-point controller is an analogy to test, not an established diagnosis.

**Experiment.** Evaluate a fixed mutation neighbourhood for selected viable genomes on a predefined sensor grid and physical scenarios. Compare single-locus and matched-magnitude multi-locus edits; stratify by locus and starting genome. Only after identifying a bottleneck build a separate modular-controller variant. Match parameter count where feasible, mutation opportunity, initialization quality and compute. Test direct search and transfer separately so “modularity helps” is not just a better initial founder.

**Readouts.** Fraction of viable edits; functional improvement; collateral loss in other tasks; reversibility; transfer across light/nutrient settings. Actuator response locality is a mechanistic descriptor, not itself fitness. Use neutral/silent edits and shuffled sensor labels as controls; the latter is a negative fixture, not a valid ecological intervention.

**Advance/stop.** If the existing architecture admits a broad useful neighbourhood, prefer better search and ecological incentives to a genome redesign. If a modular variant helps only its trained tasks, report that limit. Any controller-layout change needs versioned encoding, migration decisions and CPU/WGSL parity. **Deliverable:** mutation-effect matrix and a go/no-go argument for a separately versioned architecture.

### I06 — Construction that opens another niche

**Question.** Can one variant change the environment so that another gains a capability, and can that dependency survive fresh tests? **Sources:** [Assembly theory](https://www.nature.com/articles/s41586-023-06600-9), [Lenia](https://arxiv.org/abs/1812.05433), [stepping stones](https://link.springer.com/book/10.1007/978-3-319-15524-1).

**Implementation.** Extend the existing discovery design's conditioned-field experiments. Start with polymer, chemical fields and current transport rules. A builder conditions a world; a receiver is tested in that field. No new organism abstraction or predation actuator is needed. The “second niche” is an assay outcome, not a named ecological role assigned by code.

**Experiment.** Builder, nonbuilder and cost-retaining ablation start with the same budgets. Compare whole conditioned fields, matched-inventory spatial reconstructions and receiver-alone inoculum controls. Explicitly distinguish builder-present co-culture from builder-removed transfer. Reserve the receiver inoculum inside the initial matter/energy budget; do not overwrite occupied cells or erase polymer without recording transformed material and energy.

**Readouts.** Receiver survival, growth, measured flux use and spatial dependence; builder cost; inventories before/after transfer. Exact per-step flux attribution requires non-saturation and adequate sampling. A census sample cannot be integrated as though it recorded every intervening reaction.

**Advance/stop.** First establish a causal environmental benefit on fresh seeds. Next ask whether accessible mutations generate the builder and receiver. A later A+B→C capability test must predeclare C and compare A alone, B alone, A+B and resource-matched controls. More biomass after conditioning alone does not establish construction; more initial stored energy can explain it. **Deliverable:** budget-audited transfers, two-stage causal assay and a dependency graph with supported and unsupported edges.

### I07 — Construction grammar and copy number

**Question.** Can repeated, difficult-to-construct structures distinguish selected organisation from noise in these simulations? **Source:** [Assembly theory](https://www.nature.com/articles/s41586-023-06600-9).

**Implementation.** Build a read-only, explicitly *assembly-inspired* observer. Define primitives, allowed joining operations, object boundaries, rotation/translation equivalence and copy identity before computing a score. Start with exact small synthetic objects whose minimal construction is enumerable. For large lattice patches use a bounded grammar search and label its output an upper bound or heuristic, not an exact assembly index. Compression ratio is not automatically assembly index.

**Experiment.** Calibrate against repeated tiles, deterministic crystals, random fields, random fields with duplicated motifs, manually assembled hierarchies and evolving worlds. Match occupied mass and observation resolution. Compare reconstruction cost and multiplicity separately before considering any combined statistic. Test sensitivity to segmentation and temporal sampling.

**Readouts.** Construction-length estimate/bound, copy count, persistence, uncertainty in equivalence classes, and incremental predictive value over simple compression and occupancy. Add destruction/reconstruction interventions to connect the measured organisation to a capability.

**Advance/stop.** Reject a life-detection claim if duplicated random motifs score as strongly as the proposed positive cases. If object definitions dominate conclusions, publish the sensitivity failure rather than tuning boundaries until treatment wins. Do not optimise this metric and then use it as held-out evidence. **Deliverable:** grammar specification, exact toy tests, streaming patch sampler and an observer calibration report. This is a promising measurement project, not a settled solution to detecting selection.

### I08 — Collective sensing under moving light

**Question.** Does local interaction improve navigation under unfamiliar light trajectories, beyond independent responses or a hard-coded heading? **Sources:** [Boids](https://www.red3d.com/cwr/boids/), [Lenia](https://arxiv.org/abs/1812.05433).

**Implementation.** Begin with `planet-followers`, `planet-sensing`, `planet-wander` and the existing signal/adhesion controls. These already contain blind and sensing strategies. A new experiment changes the light schedule and comparison design; a Boids-like alignment actuator is a later rule fork only if needed. Do not call existing signal-gradient following a new flocking mechanism.

**Experiment.** Fixed-speed sun during screening; reversed, paused and wandering light during transfer. Match light exposure budgets as far as possible and report differences. Compare isolated and grouped inocula, signal on/off, motility on/off, and blind drifters. Separate signal production cost from information where supported; any cost-preserving replacement must be specified and ledger-checked.

**Readouts.** Light capture per input energy, tracking lag, group cohesion, individual motion and survival. Whole-field drift or common environmental forcing can create apparent collective motion, so measure residual coordination against independent agents exposed to the same sun. Assess whether a benefit follows group composition across a common-garden transfer.

**Advance/stop.** A group-level improvement requires a causal interaction benefit exceeding matched independent response. Schooling appearance alone is a visual success, not higher-level individuality. **Deliverable:** controlled navigation benchmark and a public world where a visitor can reverse the sun and compare blinded strategies.

### I09 — Conservative particle ecology

**Question.** Do discrete moving material units make mixing, boundaries and lineage continuity easier to measure than the current field? **Source:** [Particle Life](https://github.com/tom-mohr/particle-life).

**New simulation.** A separate particle world with fixed total material, local attraction/repulsion and a finite energy reservoir charged by environmental input. Begin with labelled inert particles. Add reaction/state transitions only after the transport ledger is exact. Formation of clusters should emerge; assigning particle labels is not assigning organism identities.

**Engineering.** CPU fixed-point reference first; bounded integer positions/velocities, explicit pair order, spatial bins and deterministic collision resolution. Equal-and-opposite impulses alone do not guarantee energy conservation under rounding; state the momentum/energy convention and heat sink. Mass conservation alone must not be called full thermodynamic fidelity. Add GPU parity only after a small-world replay suite passes. Keep a separate schema and rule identifier; reuse the viewer and bundle interfaces through an adapter.

**Experiment.** Symmetric versus asymmetric interaction matrices, fixed versus heritable types, passive clustering controls and phase-space perturbations. Compare with a field-world toy case at matched density and input budget; do not equate their time units or claim one is more alive from visual preference.

**Readouts.** Cluster lifetime, exchange between clusters, causal descendant material contribution, compositional persistence and cost. A stable attractive aggregate is not a reproducer. **Advance/stop:** retain as a useful alternative only if it improves a specific measurement or produces a testable new capability. Stop if gains are only easier animation. **Deliverable:** small integer particle engine, proof-oriented ledger tests and a cluster-exchange demonstration before any long evolutionary run.

### I10 — Regenerating neural tissue

**Question.** Which local update rules support persistent repair, and can the observer distinguish repair from repeated image formation? **Source:** [Growing NCA](https://distill.pub/2020/growing-ca/).

**New simulation.** A separately labelled neural cellular automaton with visible and hidden channels, local perception and stochastic updates. Reproduce one small growth/persistence/damage task before introducing ecology. Training is external design. It is not a naturally evolved organism, and NCA channels do not inherit the current engine's matter conservation just because both use a grid.

**Experiment.** Compare growth-only, persistent-state-pool training and damage-augmented training under matched optimisation budgets. Hold out wound shapes, wound times and rollout horizons. Include seed-only restarts and dead-cell masks so regeneration cannot be mistaken for drawing the target anew from an untouched seed. Later test removing target-image loss in favour of a physical task, with explicit resources.

**Readouts.** Long-horizon stability, task recovery, morphology recovery, out-of-distribution damage response, update-order robustness and compute. External training seeds and test rollout seeds are separate replicates. Quantise a trained model only as a distinct engineering study and measure the lost behaviour; float training results do not establish bitwise replay on every GPU.

**Advance/stop.** First earn a robust engineered-repair benchmark. Only then ask whether evolutionary mutation can retain or improve it, and report the inherited prior from training. **Deliverable:** an interactive repair exhibit plus observer fixtures; potential later integration is a separate decision because the physical semantics differ.

### I11 — Code soup and Red Queen arena

**Question.** Can useful copying appear in a minimal executable medium, and does competition improve generality independently of diversity? **Sources:** [Core War](https://corewar.co.uk/), [DRQ](https://sakana.ai/drq/), supplementary [Computational Life](https://arxiv.org/abs/2406.19108).

**New simulation.** Two intentionally separate modes over a deterministic bounded virtual machine: an arena of externally proposed programs and a soup of initially random programs. Host evaluation executes only the VM instruction set, never generated JavaScript, shell commands or native code. Fixed instruction fuel, memory length, scheduler and seed are part of the world identity.

**Experiment.** For the arena, compare mutation-only and model-generated proposals with equal evaluation budgets, tracking model cost separately. Freeze an opponent holdout and use position swaps. For soup, compare interaction, mutation-only random walk and interaction with blocked transmission, matching opportunities/programs examined. Use a direct copying assay, not only abundance or compression. The supplementary BFF follow-up in the dossier motivates separating first appearance from takeover; it is not a claim about this unbuilt VM.

**Readouts.** First validated copier, appearance rate per evaluated program, expansion rate, copying fidelity, opponent generality, behavioural diversity and provenance. Run multiple independent soups; repeated descendants are not independent discoveries. Standard Core War declares warriors and an execution framework, so success there cannot establish undeclared individuality.

**Advance/stop.** A successful arena can ship as an educational competitive world. A soup-origin claim requires the direct detector and matched nulls to pass; a takeover caused by an injected program remains a seeded experiment. **Deliverable:** VM specification, a copying/noncopying fixture suite, replay viewer and separate arena/soup reports.

### I12 — Evolution of local controller programs

**Question.** Does a small compositional program genome make useful new behaviours more accessible than fixed neural weights? **Sources:** [AutoML-Zero](https://arxiv.org/abs/2003.03384), [FER](https://arxiv.org/abs/2505.11581).

**Rule fork.** Replace the controller only in an explicitly versioned experiment with a bounded typed instruction sequence: integer arithmetic, bounded sensor reads, local state and existing actuator outputs. No arbitrary memory access or global sensors. Define overflow, division by zero, fuel exhaustion, mutation and state inheritance. Begin without persistent memory so changing representation is not confounded with adding memory; add a memory arm separately.

**Experiment.** Compare with the current controller at matched initial task performance, sensor/actuator access and evaluation budgets. Count program execution cost, not only genome length. Evaluate random search, point mutation and instruction duplication/deletion. Keep known neural-controller solutions as performance references without assuming a compiler can translate all of them exactly.

**Readouts.** Viability, useful mutation rate, transfer, behavioural repertoire and compute per accepted variant. Track bloat and degenerate no-op solutions. Exact phenotype equivalence on finite probes is weaker than equality over all reachable states.

**Advance/stop.** Build only after I05 identifies a representation constraint worth addressing. Stop if improvements disappear at matched compute or arise solely from extra memory. **Deliverable:** typed interpreter spec, CPU/GPU equivalence fixtures and an architectural comparison, with checkpoint and mutation replay support before ecological deployment.

### I13 — Discover laws without changing the question

**Question.** Can an automated proposer find better candidate local rules while a fixed verifier preserves the intended physical problem? **Sources:** [AlphaEvolve](https://arxiv.org/abs/2506.13131), [ASAL](https://arxiv.org/abs/2412.17799).

**Offline design tool.** Use a small domain-specific rule language, not unconstrained edits to the repository. An initial version searches validated parameters or bounded reaction/routing choices. Each candidate is immutable and evaluated outside the production lab. Never allow a candidate to edit its tests, score, parser or budget. Keep optimisation of kernel speed separate from scientific changes: a speed optimisation must preserve all dynamics.

**Experiment.** Compare random/structured parameter search with model-guided proposals at equal verifier budgets. The verifier checks types, arithmetic bounds, exact conservation, CPU/GPU golden parity where GPU code exists, and finite-run behaviour. Proof obligations for all allowed states are separate from sampled tests; neither claims to prove emergent life. Withhold challenge regimes from the proposer.

**Readouts.** Valid-candidate yield, held-out capabilities, failures, evaluation cost and novelty of causal mechanism. Retain failed proposals and verifier diagnostics to reveal repeated loopholes. Generated code, if later allowed, runs only in an OS-isolated process with no secrets or network and explicit resources.

**Advance/stop.** Advance when the proposer beats a cheap baseline under a fixed independent verifier. If it exploits a detector, repair and version the detector, discard contaminated holdouts and start a new comparison. **Deliverable:** candidate grammar, immutable evaluator, proposal ledger and a small set of human-reviewable rule diffs. No candidate automatically becomes the default ecology.

### I14 — Predictability atlas and observer benchmark

**Question.** Which apparent innovations survive prediction and null tests, and how does this depend on observation scale? **Sources:** [Conway's Life reference](https://en.wikipedia.org/wiki/Conway%27s_Game_of_Life), [computational irreducibility](https://www.wolframscience.com/nks/p737--computational-irreducibility/), [Boids](https://www.red3d.com/cwr/boids/).

**Implementation.** Add tiny replayable fixtures: static/periodic Life patterns, translating patterns, a supplied copier fixture where available, random fields, passive aggregates and existing ecology clips. A side-by-side teaching view shows the same observer applied to every substrate. Life is a calibration world, not evidence that chemistry and energy bookkeeping are unnecessary.

**Experiment.** Fit simple persistence, periodicity and local-statistical predictors on fixed early windows; compare prediction error at multiple horizons and frozen spatial resolutions. Keep raw prediction error separate from compression and capability novelty. Shuffle time, shift phase and duplicate motifs as controls. A prediction benchmark must use only past information; avoid normalisation fitted on the entire future trajectory.

**Readouts.** Predictive loss, recurrence, calibration, false alarms and sensitivity to binning. An incompressible random movie is hard to predict without being alive. Failure of our predictors does not demonstrate Wolfram's computational irreducibility; that is a much stronger statement about shortcuts.

**Advance/stop.** Use this suite to reject weak metrics before they enter I01 or I07. It earns no open-endedness claim. **Deliverable:** a fast deterministic fixture library and an accessible “why this is not yet evidence of life” comparison page.

## Agent execution contract

### Scope and invariants

These are idea plans, not authorisation to execute every study. The current task produces documents only. A future implementation should choose one ID, restate its bounded question, inspect the then-current checkout and reserve its own experiment identity. Prior budgets in historical notes are not new spending authority.

Preserve default config hashes for observer-only changes. Intended dynamics changes require the repository's rule-version procedure and deliberate golden-hash changes; do not hide a dynamics change under an innocent-looking optional key. Optional settings must remain absent from `defaultConfig()` when preserving existing serialized defaults. A genuinely new substrate gets an explicitly separate rule/schema identity rather than borrowing the chemistry engine's claims.

CPU and WGSL implementations must agree bit for bit for shared integer rules. Extend arithmetic bounds in `docs/rules.md`, validation and overflow fixtures before adding an operation. Keep checkpoint physics and observer state paired under their digest, and prove segmented equivalence for new checkpointed state. Do not weaken inferred-individuality claims by switching on declared-cell rules without labelling the experiment.

Current optional capability genes and inherited kernel shape share a layout byte: `genes` and `shapeReach` cannot be combined without a layout migration. Gene configurations also reject the existing neutral and declared-cell modes; choose valid, explicitly described controls rather than bypassing validation.

### Common protocol to fill before the first scientific run

| Field | Required content |
|---|---|
| Identity | Idea ID; question; repo SHA; rule/schema/metric versions; full config and preset identities; hashes of founders, candidate genomes and observation code |
| Sampling | Independent unit; development/screening/confirmation splits; seed reservations; inclusion/exclusion rules; no cross-split source histories |
| Intervention | Exact operation, time, spatial rule, before/after inventories, resource destination and sham |
| Estimand | One primary outcome and effect threshold; secondary outcomes; expected direction; why the assay is sensitive |
| Design | Arms, pairing, position swaps where applicable, number of independent blocks, horizon and cadence |
| Decision | Fixed-sample or prespecified sequential test; multiplicity control; extinction/censoring; confidence intervals; measurement-limited category |
| Provenance | Commands, hardware/backend, source/model/encoder versions, prompts when used, selection history, failed attempts and immutable input manifest |
| Budget | Benchmark steps/s on the actual device; proposal/evaluation counts; model tokens/cost if relevant; stop cap and checkpoint/restart policy |
| Interpretation | What a positive, negative or uninformative outcome establishes, and what it cannot establish |

No generic sample count makes every study adequate. Calibrate assay sensitivity first, then choose counts for its estimand and detectable effect. Historical probability gates (such as 32-replicate M3 retests) apply only where their original protocol applies; do not copy them into every new test. In search comparisons, independent search runs are the unit; in migrating populations, the connected metapopulation is the unit.

### Implementation slices and acceptance

1. **Evidence fixture.** Reproduce an existing relevant result or construct a known-history physical fixture. Include a negative case that would fool the naive metric. Finish before adding search pressure.
2. **Small CPU path.** Implement the minimum observer/assay and produce a manifest plus machine-readable evidence. Observers must not change physics; compare instrumented and plain twins.
3. **Replay and backend qualification.** Test deterministic replay and the actual new invariants. GPU work needs GPU evidence, not a mocked adapter result. For CPU-only observers, explicitly state that limit.
4. **Bounded pilot.** Benchmark runtime and calibration, choose the protocol, freeze held-out inputs, then collect scientific data. Do not tune on confirmation outcomes.
5. **Independent read-only review.** Use `gpt-6.1-sol` at high effort per `AGENTS.md`, at phase boundaries and before commits. Resolve evidence and interpretation errors as well as code defects.
6. **Human result.** Publish a replay, effect/uncertainty, failed cases and a clear decision. Report implemented/local/hosted/physical-GPU evidence separately.

Typical applicable verification commands are `pnpm typecheck`, focused `pnpm vitest run <test-file>`, `pnpm test`, and `deno run -A tests/deno/gpu_golden.ts` for changes to shared dynamics. Segmentation/checkpoint changes additionally need `tests/deno/segments.ts` and `tests/deno/stitch.ts`. Use the repo's actual scripts and local instructions at implementation time; these are not claims that those tests ran during this document task. A new package must update all four alias maps listed in `AGENTS.md`.

## Source dossier — Search and automated discovery


### ASAL — Kumar et al. (2024; arXiv v2 May 2025)
[Paper](https://arxiv.org/html/2412.17799v2), [user-supplied abstract](https://arxiv.org/abs/2412.17799), [project and demos](https://pub.sakana.ai/asal/).
Uses foundation-model image representations for three tasks: text-target search, temporal novelty, and illumination across simulations. Tested substrates include Boids, Particle Life, life-like cellular automata, Lenia and NCA. Target search uses CLIP with Sep-CMA-ES; illumination uses a genetic search retaining diverse simulations. Temporal novelty minimizes similarity to earlier embedded frames; illumination measures nearest-neighbor difference across simulations. CLIP/DINOv2 comparisons outperform pixel representations qualitatively for human-aligned diversity. The atlas is a presentation of discovered behavior, not a biological validation. Its finite observation windows and representation-relative novelty do not establish indefinite evolution, causal individuality, heredity or ecological closure. The project page supplies useful demos but is not independent corroboration of the paper.

### Digital Red Queen — Kumar et al. (2026)
[Paper](https://arxiv.org/html/2601.03335v1), [abstract](https://arxiv.org/abs/2601.03335), [project explanation](https://sakana.ai/drq/).
Evolves Redcode programs against a growing archive of previous champions, using LLM mutation within MAP-Elites. Descriptors are spawned processes and memory coverage. Held-out human warriors assess generality. Across 96 runs, generality increases while behavioral diversity across histories decreases and within-history change slows. Limited-history comparisons study cycling. Removing the diversity archive hurts optimization. Crucial distinction: the paper finds competitive robustness and convergence, not indefinitely expanding ecological diversity. LLM proposals import an external prior; they are not mutations arising spontaneously inside the simulated world. A growing opponent archive also dilutes each new opponent's effect.

### MAP-Elites — Mouret and Clune (2015)
[Paper](https://arxiv.org/html/1504.04909v1), [abstract](https://arxiv.org/abs/1504.04909).
Stores high-performing solutions across a discretized, user-selected behavior space. A candidate competes within its descriptor cell rather than only for one global optimum. Cross-cell stepping stones can help reach solutions that direct optimization misses. Demonstrations include neural networks and soft robots. Descriptor coverage is conditional on chosen axes; it is not a coordinate-free measure of diversity or evidence of open-endedness. The HTML header contains an inconsistent generated preprint date; cite the arXiv submission record (20 April 2015), not that header.

### AlphaEvolve — Novikov et al. (2025)
[Paper](https://arxiv.org/html/2506.13131v1), [abstract](https://arxiv.org/abs/2506.13131).
An evolutionary coding system generates changes to designated code, executes machine-gradeable evaluators and retains useful programs in a database. Multiple scores and rich evaluator feedback support search; the user supplies the evaluation contract. Applications span mathematical constructions and computing infrastructure. Its ability to improve code does not solve the problem of choosing a valid scientific objective. This is a methodological inspiration for a local proposer/evaluator loop, not evidence that the exact AlphaEvolve service or implementation is available here.

### AutoML-Zero — Real et al. (2020)
[Paper](https://arxiv.org/html/2003.03384v2), [abstract](https://arxiv.org/abs/2003.03384).
Searches programs built from low-level mathematical instructions, with Setup, Predict and Learn components and scalar/vector/matrix memory. Regularized evolution mutates instructions, operands and whole components. Separate search, selection and final-test tasks limit overfitting; cheap proxy tasks and functional-equivalence checks improve throughput. The work demonstrates discovery of learning algorithms under an externally supplied training/evaluation scaffold. “From scratch” does not mean no design assumptions or emergent organism reproduction. Its floating-point execution and supervised-learning interfaces are not drop-in replacements for this repo's bounded integer controllers.

### Akarsh Kumar's website
[Homepage](https://akarshkumar.com/).
Verified as an author-maintained index linking ASAL, DRQ and the Fractured Entangled Representation (FER) hypothesis. Useful for provenance and follow-up paper discovery, not a separate empirical result. It describes interests in open-ended systems, environment generation and self-play. It also links the Stanley/FER MLST interview supplied by the user; consult the primary FER paper for technical claims rather than infer them from the documentary title.


## Source dossier — Theory, representation and computational life


### T1 — Assembly theory: read via authors' institutional PDF

Original: <https://www.nature.com/articles/s41586-023-06600-9>
Accessible paper: <https://eprints.gla.ac.uk/305433/1/305433.pdf>
Title: *Assembly theory explains and quantifies selection and evolution* (Sharma, Czégel, Lachmann, Kempes, Walker, Cronin, 2023).

The paper combines an object's shortest recursive construction path (assembly index) with copy abundance. Its ensemble measure is `A = sum_i exp(a_i) (n_i - 1) / N_T`. The authors model discovery and production in assembly spaces; crucially their selection model specifies differential reuse rather than modelling every functional mechanism. Application requires physically meaningful primitives and combination operations. This suggests measuring repeated construction rather than treating visual intricacy or compression as evidence of life. It does not establish that any compression measure, arbitrary image motif count, or high index proves Darwinian evolution. Nature's direct fetch redirected to inaccessible authorization; the University of Glasgow PDF supplied the paper. For a counterpoint by a research author see <https://link.springer.com/article/10.1007/s00239-024-10163-2> (title: *Assembly Theory: What It Does and What It Does Not Do*); it disputes expansive evolutionary interpretations.

### T2 — The supplied “FEP” URL is FER, not the free-energy principle

<https://arxiv.org/abs/2505.11581>
Full text: <https://arxiv.org/html/2505.11581v1>
Title: *Questioning Representational Optimism in Deep Learning: The Fractured Entangled Representation Hypothesis* (Kumar, Clune, Lehman, Stanley, 2025).

A position paper comparing evolved Picbreeder CPPNs with SGD networks reproducing the same images. Output similarity can mask different internal organization. The authors use neuron visualizations and perturbations to motivate fractured/entangled versus unified/factored representations. Picbreeder combines human selection, historical open-ended search and NEAT topology growth. The paper explicitly leaves the relative contributions of the algorithm and objective-free search unresolved. It is not evidence that evolution always gives modular control, or that this project's fixed-point network has FER. Do not add an active-inference/FEP project based on this mislabeled URL. The relevant experiment here is representation locality, mutation locality and transfer under matched capacities and histories.

### T3 — Why Greatness Cannot Be Planned: publisher preview, not entire book

<https://link.springer.com/book/10.1007/978-3-319-15524-1>
Kenneth O. Stanley and Joel Lehman, 2015. Publisher overview and chapter list accessed; full book subscription text was not read. Its central argument challenges narrowly objective-driven routes to innovation and favors discovery through serendipitous stepping stones. ### T8 — Supplementary primary paper: Computational Life

<https://arxiv.org/abs/2406.19108>
Full text: <https://arxiv.org/html/2406.19108v2>
Agüera y Arcas et al., 2024, *Computational Life: How Well-formed, Self-replicating Programs Emerge from Simple Interaction*.

Random code strings interact by execution and self-modification in several computational substrates; the authors report self-replicators emerging without an explicit fitness landscape, with and without background mutation. They also report a substrate where replication is possible but not observed to arise. This motivates comparing substrates and detection methods. It does not imply all universal languages reliably discover replication, nor that code replication demonstrates a materially closed ecological life cycle.

### T9 — Supplementary primary follow-up: important counterevidence

<https://arxiv.org/abs/2607.01483>
Full text: <https://arxiv.org/html/2607.01483v1>
Knierim, Versari, Obryk, Agüera y Arcas, Saurous, 2026, *BFF: Simple explanations for complex phenomena*.

Direct self-replicator detectors distinguish initial appearance from population takeover. The authors find tuned random-walk mutation can discover BFF self-replicators faster than paired computation, counting programs visited; limitations on ancestry merger depth/width prevent takeover rather than emergence. They caution that dyadic interaction of short fixed-length tapes is not a particularly effective model of recombination or horizontal gene transfer. Detection tolerates unused bytes and multi-step cycles instead of demanding naive full-string identity. Any browser-life code-soup experiment should include these controls and endpoints from its start.


## Source dossier — Substrates and local interaction


### Lenia — Bert Wang-Chak Chan (2018/2019)
Read abstract and full HTML: <https://arxiv.org/abs/1812.05433> and <https://arxiv.org/html/1812.05433v3> . The supplied paper defines a continuous-state CA using a neighborhood kernel, nonlinear growth, and clipped updates. It catalogues more than 400 patterns in 18 families. Crucially its introduction explicitly says self-replication had not yet been discovered in this system. Its biological vocabulary describes pattern morphology and dynamics, not demonstrated evolution of organisms. The additive/clipped update is not the conserved-matter rule used here.

**Transfer:** compare bodies by shape, motion, oscillation and perturbation response; explore kernel architecture without treating visual complexity as life. Do not replace the exact matter ledger with Lenia's original growth update.

### Growing Neural Cellular Automata — Mordvintsev, Randazzo, Niklasson, Levin (2020)
Read full article: <https://distill.pub/2020/growing-ca/> . Training local neural updates to a target image produces growth; reusing evolved states through a training pool supports persistence; adding damaged states improves regeneration. These are different training regimes, and their distinctions matter. This is trained morphogenesis toward an externally supplied target, not spontaneous Darwinian evolution. Its developmental update is not a closed material budget.

**Transfer:** independently test growth, persistence and recovery; sample starting states throughout trajectories instead of only clean seeds. Use NCA as an engineered positive control for recovery observers. Keep any trained controller's provenance separate from ecological evolution.

### Conway's Game of Life
Supplied overview read: <https://en.wikipedia.org/wiki/Conway%27s_Game_of_Life> . Technical rules verified in first-party simulator documentation: <https://golly.sourceforge.io/Help/Algorithms/QuickLife.html> . Golly specifies Life as B3/S23 on an eight-neighbor Moore neighborhood and distinguishes related rules, including HighLife B36/S23. A deterministic binary CA is an inexpensive substrate for testing pattern classification and temporal observers. A moving or cycling pattern is not evidence of ecological novelty.

**Transfer:** a deliberately simple observer calibration world. Known static, periodic and translating fixtures make false discovery visible before applying Naturalist metrics to the ecology.

### Boids — Craig Reynolds
Read author page: <https://www.red3d.com/cwr/boids/> . Separation, alignment and cohesion act locally; neighborhoods depend on distance and viewing angle. The model supplies individual agents and steering behavior, with organized group movement emerging. The author discusses spatial partitioning to avoid the naive all-pairs neighborhood cost.

**Transfer:** group-level motion metrics and controlled perception experiments. Do not call a direct Boids port emergent individuality: individual boids are built into that substrate.

### Particle Life — Tom Mohr
Read supplied repo: <https://github.com/tom-mohr/particle-life> . It is a Java simulation framework; README explicitly says development moved to <https://github.com/tom-mohr/particle-life-app> and this repository no longer receives updates. Read implementation <https://raw.githubusercontent.com/tom-mohr/particle-life/main/src/main/java/com/particle_life/Physics.java> : nearby pairs use a type-indexed interaction matrix, friction and velocity integration; spatial containers restrict neighbor scans. Matrix reciprocity is not enforced by this update. This is a framework, so the accelerator implementation also determines the exact force law. Inspect that before attempting faithful reproduction.

**Transfer:** compare reciprocal versus asymmetric interactions, stable clusters versus persistent exchange. Conserving particle count alone does not establish the repo's matter/energy ecology or heredity. Original Java code is GPL-3.0; a conceptually inspired implementation should not silently copy it into incompatible project licensing.

### Core War
Supplied <https://corewar.co.uk/> and the attempted standards page returned 403 through browsing. Alternative practitioner-authored technical tutorial read: <https://www.corewars.org/docs/guide.html> . It describes Redcode programs in circular shared memory, execution by MARS, relative addresses, process queues, copying and process termination. The tutorial identifies its dialect as the ICWS '94 draft with pMARS extensions. A copied instruction and a new execution process are distinguishable events. Classic Core War gives each competing program its own queue, so organism boundaries and scheduling entitlement are partly declared by the runtime.

**Transfer:** exact, inspectable causal histories of instruction copying; adversarial evaluation against historical opponents. A custom energy-budget VM is a new substrate, not a faithful Core War benchmark, and must be labelled accordingly.
