Before anything else

From a fresh clone:

pnpm install
(cd apps/coordinator && mix deps.get)

Run pnpm install before any deno run: otherwise Deno 2.9 writes workspaces into package.json (CLAUDE.md). The second line is what bin/dev asks for when the coordinator's dependencies are missing; it needs Elixir. GPU commands need Chrome with WebGPU or Deno's native WebGPU. Commands marked "this Mac" read runs/, which is gitignored and exists only in the main checkout; set RUNS to it first. Every printed deno run carries --no-lock, so it leaves deno.lock alone (CLAUDE.md). The Playwright commands use the installed Google Chrome (channel: "chrome") and start their own Vite on port 5174, which must be free (BL_E2E_PORT picks another; playwright.config.ts). Run every command from the repository root, in each new terminal too.

RUNS="$HOME/develop/browser-life/runs"

1. Lab

What it is now. The lab (/lab/) runs a world in the browser on WebGPU. Pond keeper is built on the breeder: a log of firsts with rules stated in advance, a session card and a session file that tools/run.ts replays to the same final hash (#20); a pressure dial, auto-breed, Keep a lineage and a "What's next?" ladder (#25); a family tree and pond firsts (#31). A Field notes panel scores gradient-m3 and spots-m3 worlds against a neutral baseline and files notes only at the rule fixed for each world beforehand (#52). A ring says the world differs in kind from neutral runs, not that something arose inside it, and the spots-m3 threshold is set by one run (held-out bound 25.9%) (#52). Each note offers the rule proposer's follow-up, applied only when you click (#56). Lab accessibility fixes cleared the lab exclusions the public accessibility spec held (LAB_HELD); two hand-reviewed exclusions remain, each measured by the spec (#46). Each PR's own gates (vitest, Playwright in Chrome) verified it. Not deployed.

3. Archipelago

What it is now. The Phoenix coordinator (apps/coordinator) cuts runs into segments, hands them to islands (the browser's /island.html or the headless tools/island.ts), has a fraction replayed by a second island and compares state hashes; tools/stitch.ts turns segments into run bundles (README.md). Bred pond worlds now travel too: the breeder preset and the 21 pond-breed-, pond-mass- and pond-drift- conditions run, verify and stitch on islands that advertise breed-v1 (#33). Islands stop cleanly on Ctrl-C or Stop (#43). The coordinator checks its limiter settings at boot, refuses a garden token in a query string and keeps each island's capabilities for operators (#45). The operator page shows gardens, bred runs, limits and failures behind the admin token (#39). Verified by (cd apps/coordinator && mix precommit) and tests/deno/coordinator_integration.ts (86 PASS in #33 and #45). Not deployed.

Try it locally. The lab and the coordinator together (stop a pnpm dev from the sections above first, or use the coordinator-only command below: bin/dev asks for port 5173, which Vite will not share, apps/lab/vite.config.ts):

bin/dev

or the coordinator alone:

(cd apps/coordinator && mix phx.server)

Create an experiment, then run two islands, each in a terminal of its own (or one plus http://localhost:5173/island.html in a WebGPU browser). A run's final segment is always replayed by a different island, and tools/stitch.ts stitches a run only once that replay is done; with one island it lists every run and skips it (--allow-unverified stitches anyway):

curl -X POST localhost:4000/api/experiments -H 'content-type: application/json' -d '{"experiment":"a1","presetId":"gradient","conditions":["treatment","neutral"],"seeds":[1,2,3],"steps":100000,"segmentSteps":5000,"censusEvery":100,"verifyFraction":0.1}'
deno run -A --no-lock tools/island.ts --coordinator http://localhost:4000

The operator page is http://localhost:4000/index.html. When runs finish:

deno run -A --no-lock tools/stitch.ts --experiment a1 --out /tmp/stitched

Without --out it writes to runs/a1/ in the checkout you run it from.

tools/island.ts takes --coordinator, --tasks and --garden-token=<t> (its header); it has no --help.

How this page was written (rules fixed before writing, 2026-10-18)

These rules were written before any of the status on this page, against origin/main at 34621dc2 (PR #53). The final origin/main commit the page describes is 5e7bda5c (PR #57), checked again with git fetch at ship time (18 Oct, 15:44).

  1. Sources. Every claim comes from a merged PR's body or a dated doc on origin/main, and names its PR or file. Nothing comes from memory or from a session's notes. The backlog run's decisions log (PR #40, not on main) is cited by its D-number only for what waits on the user.
  2. Built, verified, deployed. "Built" means merged to main. "Verified" means a merged PR's own gates ran it, and the page says which PR. "Deployed" is said only where a deploy record says so; nothing merged in this run was deployed (D-04), and the page says so once per app instead of implying anything is live.
  3. Open work. An open PR or a slice without a merged PR is named in one clause, never described as built. PRs that merge before the ship-time fetch are included; the rest are not.
  4. Results. A result is labelled with DESIGN.md's vocabulary (Measured, Negative, Not yet measured, Unclear) as its PR labelled it, never upgraded.
  5. Commands. Every command on the page appears in the table at the end with one of three checks: Ran (run here on this checkout, with its exit code and uptime), Read (its flags checked against the code or script that defines it, with the file named), or Needs data (it reads run bundles under runs/ or a GPU that a fresh clone lacks; the page says which). A command that cannot be checked one of these ways is left out. No --help is claimed for a tool that has none.
  6. Waits on the user. An item is listed only when a merged PR or a D-number says it needs the user's yes or decision. Each says what the default is, if one was taken, and where it is written down.
  7. Plain and short. One paragraph per app, then try it, not built, waits on you.

Clarification (2026-10-18, after writing): PR #57 merged before the status was written, so the page describes 5e7bda5c. DESIGN.md's vocabulary also has Confirmed and Seen; the page uses neither. Where a PR body gives a reading but no chip, the page uses the chip the public journal gave it (#32, #54) and says so. The gene readouts are quoted in their own rule's words (PASS, CONFOUNDED).
