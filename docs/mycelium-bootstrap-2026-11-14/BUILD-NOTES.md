# Build notes: step 1 (CPU reference), 14 Nov 2026

EXPLORATION, not a test. Uncommitted. Step 1 covers `tools/mycelium/world.ts`, `tools/mycelium/RULES.md` ("Bootstrap keys") and `tools/test/mycelium-bootstrap.test.ts`. `gpu.ts` is untouched. Where DESIGN.md was ambiguous or silent, the reading below was taken because it keeps both ledgers exact and every keyless byte unchanged.

## Readings taken

1. **Claim candidates take the full set of same-tag candidates, whatever their own deposit.** DESIGN 6.1 says "candidates whose tag equals `W2[ci]` do `Q += dep`". Implemented literally: a same-clan candidate with a smaller deposit than `W1` still adds its deposit to `Q`; a different-clan candidate with the largest deposit but a smaller tag does not. `resolveClaims` is an exported pure function so the GPU port and the tests share it.
2. **`validateState` also bounds the owner tag by the ids issued** (`Z - 1 < nextId` for `"id"`, `< nextGid` for `"gid"`). DESIGN lists only `Q <= P`, `Z == 0` iff `Q == 0`, `Z <= 0xffffffff`. The extra check catches a corrupt checkpoint; it never fails a state `step` produces (a tag is `id + 1` of a particle that existed). Tests that hand-build owner planes set `nextId` high enough.
3. **`trailInitPitch` with `"carpet"` or no pattern is rejected** (DESIGN 4.1: "only with a pattern other than carpet"). `trailInitPattern` and `trailInitPitch` both require `trailInit`.
4. **The free layer's `S[c]` sums the request of every particle that starts in the cell,** including ones that die before depositing (DESIGN: "from the same outputs as the requests"). A dead particle's share is unused, not redistributed.
5. **Free-layer counters are per-step optional fields on `StepStats` and cumulative optional fields on `Totals`,** present only when `trailFreeLayer` is. They are in the checkpoint header (hence the digest) only for F worlds. They are also checked against the 2^50 lifetime bound in `step` and `validateState`.
6. **Owner planes are appended after the genome in `encode`** (Z then Q, N u32 each). DESIGN says "append `2N` words" without the position; after the genome keeps keyless bytes identical and alignment (n * 160 is a multiple of 4). The GPU `read`/`encode` path must use the same order.
7. **Ghost shift range is `1..min(W, H) - 1`** for `trailConduitGhost` and `ownerGhost` and requires `trailConduit` / `ownerConduit` respectively (DESIGN 3).
8. **`ownerConduit` is skipped from the public-conduit branch:** `diffuse` takes the public conduit or the owner conduit, never both (validation excludes the pair).
9. **The decay of `Q` lives inside the existing `P > 0 && pDecay > 0` branch,** because `Q <= P` makes `Q > 0` imply `P > 0`, and it reuses the P draw (no new slot).

## Things the design did not say that the GPU step will need

- Claim candidates are built only for particles with `dep > 0` on a cell whose `Z` was 0 at the start of the step; `z == t` adds to `Q` in-loop; the foreign case adds to P only.
- `S` and `room` are start-of-step: `P` is only written by deposits (phase 5) and decay (phase 8), so a snapshot taken after thinking and before phase 5 is race-free.
- The eating gate must zero `r` before both the `req` store and the `R` add (tested by building an `R <= A` cell with refused strangers; a mutation that gates only the sum underflows A in that test).
- `validateConfig` bound `shiftMax = min(W, H) - 1` is computed from the config's own width and height.

## Not done in step 1

No `gpu.ts`, no parity cases, no observers, no runner. The pin and the 69 GPU parity cases are unchanged on disk (nothing under `tests/deno` was touched); the GPU parity run itself belongs to step 2.

# Build notes: step 2 (WGSL port and parity), 14 Nov 2026

EXPLORATION, not a test. Uncommitted. Touched: `tools/mycelium/gpu.ts`, `tests/deno/mycelium_gpu.ts` (additions only; 0 deleted lines). `world.ts` semantics unchanged; no CPU bug found.

## How the GPU does each key

- **P (pre-laid trail):** no shader change. `create` calls `createWorld` and `upload` writes A, C, P. Checked by a step-0 digest guard on every pattern.
- **F (free layer):** the per-cell request sum `S` is a new plane (`F.DS`, appended, cleared by `k_fl_clear`); `k_think` adds `dreq` to it; `k_grant` (which runs before `k_live` writes P) computes each particle's `fr` from the start-of-step P and stores it in a new scratch plane `T.FR`, so there is no separate room plane or `k_fl_room` kernel (DESIGN 5.3 had one; the result is the same and one dispatch fewer). `live_one` has the free/paid block gated by the baked const `FL_SET`; free and paid units are added to two per-step words and carried into (lo, hi) lifetime pairs in `k_finish`, checked against 2^50.
- **O (owner):** planes `Z`, `Q`, `W1`, `W2` appended after the F plane. The eating gate zeroes `r` before the `T_REQ` store and before the `F_R` add, in `k_think`. `live_one` adds `dep` to `Q` when `Z == tag`, or records the actual `dep` in `T.CDEP` when `Z == 0`. Claims are `k_claim_a` (`atomicMax` of dep into `W1`), `k_claim_b` (`atomicMax` of tag into `W2` among `dep == W1`), `k_claim_c` (every candidate with tag `W2` adds its own dep to `Q`); no packed compare. `k_light` then gives a cell with `Z == 0` the tag `W2` and decays `Q` with the same `draw` as `P` (and clears `Z` when `Q` reaches 0).
- **Ghost and owner conduit:** a new `send_x` / `k_send_ax` (A only) reads P at the shifted cells (`trailConduitGhost`) or Z, Q (`ownerConduit`, `ownerGhost`); `send()` and `k_send_a` are untouched, and the gather is shared. The dispatch guard is `diffA > 0 || trailConduit || ownerConduit`, as on the CPU.
- `fieldLayout(cfg)` is exported and used by the allocator; a keyless config gets exactly the old literal. `read()` returns `Z`, `Q` and the free counters when the keys are present; `upload()` takes them. `view` is unchanged (the lab does not draw owners).

## Harness changes (all additive)

`firstDiff` compares `Z` and `Q` when both sides have them and skips `freeUnits`/`paidUnits` when one side lacks them (a keyless baseline); the digest still covers them for the GPU-vs-CPU compare. New `bootstrapCases()` (all names start `bootstrap`), four resume variants appended, and `runBootstrapGuards()` (step-0 digests, keyless layout literal, rejected configs, free counter raising at 2^50 on both engines).

## Case design notes

- `diffA 128` with `ownerConduit` is expected to equal no conduit (the rate is capped at 128, so nothing is left to add); the case asserts `same: true`.
- At `pDecay 65535` every owned cell decays to nothing each step, so that case is run 20 steps one at a time and does not require a surviving claim.
- Clump cases with free layer run only 12 steps: the clump dies out and the keyless baseline would catch up on the final state.

## Defect found in an existing observer (not edited)

`observe-r2b.ts` `cloneNoDecay` copies every plane except the owner planes `Z` and `Q`, which the clone then shares with the live state. `depositMeasure` steps that clone, so in an owner world it rewrites the live `Q` (afterwards `Q > P`, `validateState` fails). It surfaced as every branch of the first owner smoke run failing validation at its first read. The runner hands the existing observers `observerView(s)` (owner planes copied) and re-checks the pristine state before any branch. A test pins both the protection and the defect. Those first O smoke lines (3 finished lines with `ledgerBadChecks > 0`) stay in the run-log, marked smoke; the outputs were deleted and the series re-run clean.

## Fixes after review (advisor), all in this step

- Owner readouts are taken from the pristine state; only the existing R2b/R4 observers get `observerView(s)` (it is that view that ends up one step ahead). A test pins that a census of the view is a different census.
- Sizing path built and exercised on smoke: `--size --out <dir>` reads every S run in the directory (use one `--out` for S1, S2, S3, S4) and writes `<dir>/sizing.json` with a `measured` list (t0, v, gR, tAlive, diffA from S1/S2; Fstar, Fg, diffAF from S3; theta from S4). `--sizing <file>` is checked per arm (`armNeeds`): a real run is refused unless every field its arms are built from was measured, so S3's treated arm waits for stage 1. `--dry` runs every gate (needs, projection) and starts nothing. `--no-gate` drops both gates and is never needed.
- Labels fail closed: fewer than 8 slots (16 after an extension), or a missing control twin, gives INCOMPLETE, never a label. `keptClass` requires the FREE-ONLY run. D's SELECT needs the deposit lift, K on/off/base and the blocked no-lift (read at strength R, the only strength D's blocked arms carry); without blocked arms it reads I.
- The read schedule adds the analysis window edges (t0, t0 + 2000, 2000, 5000, 10,000, the plateau t_alive values) so `windowSide` always finds its reads.

## Readings taken and limits

- `t0` is the larger of the uniform-light and gradient-light settle steps (the design says "median over seeds" for one world; two lights needed one number). A reading, not the design's words.
- gOwner and gCpub (owner-edge readouts, step 3c) are never measured, so O is refused unless `--no-gate`. The O label function is complete and unit-tested; `--label` issues none. The F label's H uses only the occx branch (sens and acute branches are not implemented in `analyzeF`).
- F (`analyzeF`) and D (`analyzeD`) ran on one-slot smoke data only: they have not seen a real cohort.
- Timing: the clean numbers are the R7 runs (jobs 1, 5,000 steps: 3.1 to 3.3 s per run with reads every 100, 7.8 s for 400 steps with a read and a road census every step). Rates in `--count` come from 2,000-step smoke runs in which start-up and the 25-step branch reads weigh heavily; the projection is a rough check, applied per invocation, not summed across series.
- `pnpm typecheck` does not cover `tools/`; the new modules and the test file were type-checked with `deno check` (runner) and a scratch `tsc -p` over the test file and the pure modules, both clean.
