## 1. Bounded question

PR136 ended inconclusive (underpowered): M3 clusters 4 and 9 each had A = 1 improving edit of 24 assayed, against the pre-stated minimum of 5 (`RULE.minImproving`). Question: with enough assayed edits for the unchanged rule to be able to decide, what does it decide for the same two genomes, same operator, same neighbourhood families, same scenarios and thresholds? The slice does not ask anything new about controllers and does not change the rule. Output: a verdict from `decide()` plus a go/no-go for a separately versioned controller architecture, exploratory and bounded to these two genomes, the one-step operator, the 26,244-point probe grid and the three 16x16 tiny-world biomass assays.

## 2. Design decisions (to be fixed in AMENDMENT.md before any new assay)

1. **Unchanged:** genomes (M3 c4 sparse, M3 c9 dense; generalist is control only, does not vote), operator (`mutateInPlace` through `editFromSlots`), families (single6, single24, multi2, multi4), scenarios and `ASSAY` values except `seeds`, `tau` formula, gate (1000 / 250), `viableFloor`, `RULE` (deep-equality test against PR136's `protocolRecord().rule` and a pinned snapshot). No substitution of genomes: the panel carries singleton candidate lists (`sparse [4]`, `dense [9]`), so `runStudy` cannot fall through to c10 or try c16; if a genome fails the gate under the new seeds the verdict follows the existing rule (`measurement-limited` or single-genome `inconclusive`), pre-stated.
2. **Fixed N = 192 assayed genuine non-duplicate edits per M3 genome** (8 for the generalist, as before, only for the sensitivity and neutral controls and for tau). Power argument: PR136 observed A/N = 1/24 = 4.2% per genome. With A ~ Binomial(192, p): P(A >= 5) = 0.905 at p = 1/24; 0.805 at 3.5%; 0.685 at 3.0%; 0.340 at 2.0%; 0.991 at 6.0%. Both genomes need A >= 5: 0.82 at p = 1/24 for both (independent). N = 144 gives 0.72 per genome (0.52 both); N = 240 gives 0.97 (0.95) but is not affordable at the CPU budget. The AMENDMENT states these numbers and that power below p ~ 3% is low: a second inconclusive is a legitimate outcome and still reported. **What A >= 5 does and does not buy (review P1).** `decide()` is unchanged, so the amendment states which verdicts are reachable, with numbers: (a) A >= 5 on both genomes only moves the rule out of the `underpowered` guard, into `broadly-useful`, `entanglement-signal`, or the residual `inconclusive` (disagreement or neither rule met). That residual `inconclusive` is a decided outcome of the rule, distinct from the underpowered one, and is reported as such. (b) `broadly-useful` additionally needs K >= 10% of assayed genuine edits, i.e. K >= 20 at N = 192 (K >= 15 at 144); under the binomial model at p = 1/24 P(A >= 20) is about 0.0002 (0.0011 at N = 144), so a `broadly-useful` call is very unlikely unless the true improving rate is several times PR136's. (c) `entanglement-signal` needs median breadth (over all generated genuine edits, doubled units) >= 6 doubled (3 actuators) and >= null + 2 on both genomes. An outcome-free preflight at freeze (below) computes the structural upper bound of c4's breadth: c4's outgoing W2 fan-out per hidden unit is [3,2,1,0,1,1,0,0]; a reviewer's in-memory rebuild of the proposed generator found 66 of 96 genuine w1/b1 rows with structural breadth <= 1, so the upper-bound median is at most 1 and `entanglement-signal` is unreachable for c4 on any outcome. The amendment says so up front: the achievable aim of this panel is to turn `inconclusive (underpowered)` into a mechanically decided `inconclusive (neither rule met)` or `broadly-useful`, and to report A, C, K with intervals. It must not be advertised as able to show entanglement. If the preflight confirms unreachability, the go/no-go text states that a `no-go` follows from "neither rule met" and that entanglement was never testable on these genomes; testing it would need a different genome or a rule change, each a separately versioned protocol (not done here). The 0.905 etc. probabilities are illustrative, not a guarantee: they assume IID binomial edits, whereas the draw is stratified without replacement with shared loci across magnitudes and multi-edit constituents (PR136 PLAN 2.5 noted these dependencies); the amendment labels them as such and also reports P(A >= 20) and the K threshold.
3. **Fixed N, no optional stopping:** the assayed set is chosen and committed before any new assay (freeze file below); the run assays exactly that set once. Failed or crashed runs are rerun from scratch with the same frozen set, never extended or cherry-picked.
4. **Larger neighbourhood, same families.** PR136's 94-edit neighbourhood has 8 to 10 genuine edits per small stratum, so N = 192 needs bigger pools. A new panel protocol (`panel: "power-v1"`) widens only the draw counts of the same families: single-locus slots per kind `w1 40, b1 8, w2 32, b2 8` (b kinds exhaust their pools) plus the 3 physics slots, both magnitudes, sign by counter draw; `drawsPerMulti` 64 for multi2 and multi4; the equal-slot-count secondary family is not emitted in the panel (it never entered the rule). Proposed allocation per M3 genome (sum 192): single6 and single24 each `w1 22, w2 22, b1 6, b2 6, physics 1` (57 each); multi2 39; multi4 39. Population per stratum is a function of genome and operator only, so it is counted at freeze time (no outcomes) and the allocation is adjusted there only if a pool is short, by a rule written in the amendment (deficit moved to w1 of the same family). Inverse-probability weights use the real eligible population/chosen per stratum as before. **Estimand change, declared (review P2):** the multi-locus share of the assayed set rises from 6/24 to 78/192 and physics falls from 2/24 to 2/192, and both PR136 improvements were multi2 edits, so this allocation is outcome-informed. The verdict uses unweighted A/C/K and multi-vs-single counts and the breadth median includes unassayed edits, so the same numeric thresholds apply to a different mixture. The AMENDMENT states this plainly as "the same rule read on a larger, differently mixed, fresh panel", calls the result a statement about this panel's eligible neighbourhood (not about PR136's), and reports weighted estimates alongside. To limit outcome-informed tilting the allocation is fixed by a stated structural rule (equal share per family, within family proportional to pool size), written before the preflight, not tuned on PR136 improvement counts; the proposed numbers above are replaced by that rule's output at freeze.
5. **New disjoint seeds.** Assay seeds `[101, 102]` (PR136: `[1, 2]`), same count so the `3 x seeds` term of tau keeps its meaning. Neighbourhood/selection salt `0x1c0de06` (PR136: `0x1c0de05`) and null-replicate tags prefixed `power:`. Edits whose genome hash occurs anywhere in PR136's 94-edit neighbourhoods of the same start genome are excluded from the draw, so the 192 are fresh edits as well as fresh seeds. **Eligibility (review P2):** excluded edits have zero inclusion probability, so the evidence records both `generated` (full, includes excluded rows, used for breadth and descriptors) and `eligible` (generated minus PR136 hashes) populations per stratum; selection, weighting and the population recomputation in `--check` all use the same eligibility predicate (the checker is extended to take it; PR136 passes the empty predicate). A reviewer's rebuild found c4 eligible pools of 4 for single6/b1, 4 for single24/b2 and 0 for single24/physics against requested 6, 6 and 1: the frozen deficit rule (move to w1 of the same family; physics deficit goes to w1 of single24) is applied and the final redistributed allocation is what is frozen. The page and RESULT state that estimates describe the eligible complement. A test proves: assay seeds disjoint from PR136's, salt different, no assayed hash shared with PR136's assayed or unassayed rows (read from PR136 `evidence.json`).
6. **Read on its own.** PR136's 24 edits are not pooled: different seeds, hence different baselines, tau and gate, and a different neighbourhood. The page and RESULT.md show the two panels side by side only. No cross-panel statistic enters the decision.
7. **Gate and tau under new seeds** are computed from baselines only (the same code), at freeze time, and written to `freeze.json` before the run. They are baseline facts, not mutant outcomes. If a genome fails there, the AMENDMENT records the consequence mechanically; no genome swap.

## 3. What is built (one PR, reviewable size)

1. **Evidence fixture with a negative case (reuse, extended to the new seeds).** The PR136 fixtures are re-run unchanged under the new seeds: hidden-unit permutation (same function, many bytes differ: fools "bytes changed"), dead-hidden edit, clamp edit, sensor-label shuffle (a different controller, not ecological), generalist localised edit. New negative case specific to power: a **synthetic no-signal panel** test in the library (hand-built outcome table with A = 0 and with A at 4, 5 and 6) proving `decide` returns `inconclusive` for A < 5 on either genome and that a large N with the same A fraction does not by itself change a verdict (a naive "improving rate is low so it is a null" metric would call A = 4 of 192 a no-go; the rule says inconclusive). Synthetic verdict fixtures are built from consistent row-level outcomes through `buildPayload`/`readoutFor`, never by supplying `underpowered` independently (`decide()` trusts that flag). Positive and boundary fixtures through the row-to-verdict path for both genomes: `broadly-useful` at K = ceil(10% N) and one below; `entanglement-signal` with breadth at the threshold and one below; the A = 5 boundary. The earlier phrase "same A fraction at larger N does not change a verdict" is dropped: crossing `minImproving` changes the branch, and an A = 5, K = 5 input is `broadly-useful` at N = 24 but `inconclusive` at N = 192, which a test pins. And **selection-disjointness fixtures** with independent negatives (review P2): a panel with overlapping seeds only, one with unchanged salt only, and one with a single overlapping genome hash only must each fail the disjointness check for its own reason (a combined check cannot be satisfied by the seed branch alone). **Inventory fixtures:** `recomputeProblems`/verdict construction currently accept an empty neutral-fixture set through `.every()`; the power checker requires the exact expected fixture inventory and nonempty expected sample sizes, and a test removes all fixtures and expects failure (PR136's behaviour is unchanged: the shared helper takes an expected-inventory argument that PR136 sets to its current behaviour).
2. **Panel parameterisation of the existing library (behaviour-preserving).** Thread a `Panel` record `{ id, salt, seeds, singleSlots, drawsPerMulti, secondary, allocM3, allocControl, excludeHashes, candidates: { sparse, dense }, nullNamespace }` through `buildNeighbourhood`, `drawAssaySubset`, `nullBreadths()` (which today hard-codes `${id}:null:${r}` and rebuilds neighbourhoods) and the candidate selection in `runStudy`, `AssayCache/responses/tau`, `prepare`, `runStudy`, `protocolRecord`, with `PANEL_V1` = today's constants as the default. PR136 `--replay-check` must stay byte-identical (gate). Because `tools/locality/matrix.ts --check` hashes the locality sources into `manifest.json`, editing them changes those hashes; the plan re-pins only `manifest.sources` for PR136 after the replay proves `evidence.json` is byte-identical, recorded as an explicit note in the AMENDMENT. `evidence.json` and its seal are not touched.
3. **Worker pool** in `tools/locality/pool.ts` (Deno workers; none exists, PR136 cut it). PR136 measured ~75 s serial for 24+24+8 edits, so N = 192 is roughly 8x the mutant assays, a few to ~10 minutes serial; the first gate is a baseline-only serial benchmark, and the pool is built only if serial projected time exceeds the budget (serial `--workers 1` remains the reference path either way). Tasks are (genome, edit index) assays; results are collected by index and merged in fixed order so the payload is independent of worker count; `--workers` default 2 (vitest `--maxWorkers=2` does not cap nested Deno workers; verification runs are sequential, not concurrent, and budgeted in the gates). `--replay-check` equality is asserted for 1 vs 2 workers on a small subset in a test, and for the full run in the acceptance gates.
4. **Freeze step:** `tools/locality/power.ts --freeze` computes, without any mutant assay, the panel neighbourhoods, populations, final allocation, chosen edit ids and genome hashes, generalist and M3 baselines, gate/tau, and projected runtime from timing of baseline runs. Writes `freeze.json` (sealed). Committed and pushed before the run (freeze-before-run exception).
5. **Run step:** `tools/locality/power.ts --write` refuses if `freeze.json` is missing, its seal fails, or `git` shows the freeze inputs or the power source closure (hashed in `freeze.json`) differ from `HEAD`/the pushed branch (the freeze commit is resolved externally; `freeze.json` carries source and input hashes, never its own commit hash); assays exactly the frozen edits; writes `evidence.json` + `manifest.json` (payload shape of PR136 plus `panel` and `freezeSha256`); `--check` (no simulation: seal, freeze match, recomputation of every derived field and the verdict) and `--replay-check` (regenerate and require byte equality). Reuses `checkSaved`/`recomputeProblems` by parameterising paths and protocol.
6. **Verdict and RESULT.md:** `decide()` unchanged on the new payload, applied mechanically; RESULT.md (exploratory, bounded) gives A, C, K per genome, the verdict, go/no-go, deviations, side-by-side PR136 table.
7. **Page:** extend `apps/lab/controller-locality/` with a panel selector (Original, Power-up) and a side-by-side summary table (N, A, C, K, verdict, seeds, tau); same matrix view for either panel; filter by stratum remains. Local, off the deployed site (packaging test unchanged and still passing). The power panel has about 310 generated rows per genome (2x(40+8+32+8+3) singles + 2x64 multis), not 1000. The page statically imports full evidence today, so filtering does not shrink the transfer: measure the real payload first and add a generated projection only if unreasonable (then verify summaries against full evidence). `render.ts` has no stratum/kind filter today; this slice adds one.

## 7. Non-goals and limits

- No modular controller, no search/evolution run, no new scenarios, no new mutation operator, no change to the decision rule, tau, gate or thresholds, no GPU, no paid calls, no deploy, no change to the frozen preregistration.
- Not pooled with PR136; no claim about evolved creatures in general. Biomass responses are not independent capabilities (as in PR136). Short horizon (200), tiny tile, two seeds.
- N = 192 is a power choice under the observed rate; a low true rate (about 2%) makes a second inconclusive likely (P(A >= 5) 0.34), and that is reported as such. Even with A >= 5, the go/no-go for a fork is advisory only; any controller-layout change needs its own versioned plan, migration and CPU/WGSL parity.
- Wall time depends on machine load; timing is provenance, not part of the deterministic payload.
- Entanglement on c4 is structurally unreachable (see 2.2); a RESULT of `inconclusive` is not evidence about entanglement either way.
- Optional-stopping, extra runs after seeing A, or re-drawing the assayed set are prohibited; a reviewer-found defect before the run restarts from the freeze commit with a new dated amendment.
