A mutation-effect matrix

What does one small edit to a controller change?

Each creature carries a tiny neural controller of 160 small whole-number weights. For three starting controllers we edit it a little in a fixed set of ways and ask two things: which of its eight actions does the edit move, and does an edit that helps one thing cost another?

CPU only: deterministic integer simulator and probe, no GPU evidence. Exploratory, bounded to the tested genomes, this one-step operator and three short tiny-world assays. Local experiment, kept off the public site. It is not a finding about evolved creatures in general, and it does not say whether anything here is alive.

The panels

Where the numbers land

    The matrix

    One row per edit. The eight shaded columns give the permille of the probe grid points at which that action changes; the three assay columns are paired changes against the unedited controller, summed over two seeds, with a star beyond the stated tolerance.

    Counts for the chosen controller

    Finite-panel counts with denominators, no intervals. Assayed means run in the tiny worlds: a stratified subset fixed before the full panel run, not every generated edit; AMENDMENT.md discloses earlier reduced-panel harness assays.

    Fixtures: where the easy metrics fail

    Hand-built controllers with a known history. Counting bytes changed or weight distance calls a permuted controller very different; it behaves identically on every probe point and in every assay run.

    Naive metrics next to functional ones. These rows are never in any rate.

    What this does not show

    • The probe grid is canonical, not the inputs a creature meets: no change on the grid is not proof of no change in the ecology.
    • The three tiny-world scenarios score environmental biomass response over 200 steps in a 16 by 16 tile. They are not independent capabilities, and not survival, regeneration or ecological fitness.
    • Three starting controllers and one fixed one-step neighbourhood: no population claim, no claim about evolved lineages, no walks, no combinations beyond the matched multi-locus families.
    • Counts describe the sampled edits of each controller. They are not rates over all possible mutations, and controllers are never pooled.
    • The rule that turns the counts into a recommendation was written before the outcomes were computed; the horizon, viability floor and margin were calibrated with the M3 baselines visible, and the plan's preferred dense genome failed both calibrated criteria. The recommendation is advice for a later plan, not authorisation for a new architecture.
